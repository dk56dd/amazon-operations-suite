# 差异化方案生成 Skill

中文名称：差异化方案生成  
English name: `product-differentiation-planner`

## 使用目标

帮助用户从竞品同质化、评论痛点和供应商能力中生成 2-3 个可落地的产品方案，避免为了差异化而增加无意义功能。

## 触发场景

在以下情况使用本 skill：

- 用户已有产品方向或竞品 ASIN，想知道“怎么做出不同”。
- 用户完成评论痛点分析，需要把痛点转成产品规格和卖点。
- 用户提供供应商现有款式，想判断哪些改动最值得做。

不适合使用本 skill 的情况：

- 用户只想从评论中找痛点，应先用 `review-painpoint-mining`。
- 用户需要判断能不能赚钱，应进入 `profit-cost-estimator`。
- 用户需要认证或合规判断，应进入 `compliance-certification-scanner`。

## 必需输入

- `marketplace`：站点；未提供时可按 US 预分析，并标注“站点待确认”。
- `target_keyword`：核心关键词或细分类目。
- `asins`：竞品 ASIN 列表。
- `target_price_range`：目标价格带。
- `target_user`：目标用户。
- `painpoints`：评论痛点或用户需求信号。

## 可选数据源

- 竞品图片、A+、参数表、卖点、QA、供应商现有款式。
- Sorftime MCP、卖家精灵 MCP，用于竞品销量、关键词、市场容量、价格带和评论结构。未开启时要求用户提供表格或截图。

## 数据要求

分析前先做数据完整性检查，并在输出开头写清“已满足 / 缺失 / 只能预分析”。

| 数据项 | 最低要求 | 缺失时处理 |
|---|---|---|
| 站点 | US、CA、UK、DE、JP 等明确站点；未指定时只能按 US 预分析 | 标注“站点待确认” |
| 竞品 ASIN | 至少有核心竞品或用户提供的竞品资料 | 无竞品时不能输出竞品同质化结论 |
| 价格带 | 目标售价或竞品价格带 | 无价格带时不能判断方案是否匹配市场 |
| 核心关键词 | 目标关键词或细分类目词 | 无关键词时只能按产品方向预分析 |
| 评论痛点 | 来自评论、QA、退货或用户反馈的痛点 | 无痛点时必须先进入 `review-painpoint-mining` 或要求补数据 |
| 供应商款式 | 工厂现有款式、可改项或约束 | 没有时只输出市场侧方案，不输出供应链可行承诺 |

方案必须能被供应商理解，至少落到规格、材质、结构、配件、包装、套装、颜色、说明书或质检要求之一。

## MCP 开启约束

- Sorftime MCP、卖家精灵 MCP 用于补充竞品销量、关键词、市场容量、价格带和评论结构，使用前必须先确认已开启。
- MCP 未开启时，不要编造市场容量、销量、关键词热度、竞品价格或评论结构；改为列出需要开启的数据源或要求用户上传表格。
- 只有 ASIN 但 MCP 未开启时，不能输出完整参数矩阵，只能输出需要采集的字段清单。
- 如果 MCP 数据与用户提供数据冲突，先写清口径差异，再给低置信度判断。
- 工具字段只能作为观察，不能直接复制成最终方案。

## 工作流

1. 先做数据完整性检查和 MCP 开启检查；缺少竞品、价格带、关键词或痛点时，先输出待补字段。
2. 建立竞品参数矩阵：价格、尺寸、重量、材质、套装、颜色、功能、配件、保修、适配场景。
3. 找出市场同质化区域：大家都在卖什么，哪些卖点已经失效。
4. 识别用户可感知差异：用户一眼能看懂、使用中能体验、评论里能复述。
5. 把差异化机会分为低成本快改、中等开发、高成本开发和不建议方向。
6. 生成保守版、主推版、激进版 2-3 个方案。
7. 对每个方案评估成本影响、供应链难度、侵权风险、合规风险和 Launch 压力。

## 输出合同

用中文输出，优先用表格展示方案对比和优劣势。必须包含：

| 模块 | 必填内容 |
|---|---|
| 数据状态 | 已用数据源、MCP 是否开启、缺失字段、站点口径 |
| 竞品同质化结论 | 当前市场主要同质化点和失效卖点 |
| 差异化机会清单 | 用户是否可感知、开发难度、成本影响、风险 |
| 方案 A | 低风险快上款：目标用户、核心功能、规格变化、成本影响、主图卖点、潜在风险 |
| 方案 B | 主推差异化款：目标用户、核心功能、规格变化、成本影响、主图卖点、潜在风险 |
| 方案 C | 高风险高差异款：目标用户、核心功能、规格变化、成本影响、主图卖点、潜在风险 |
| 方案优劣势 | 每个方案必须列优势、劣势、适合条件 |
| 不建议方向 | 用户不敏感、成本过高、侵权或合规风险高的方向 |
| 缺失输入 | 继续决策必须补齐的数据 |
| 下一步 skill | 利润测算、FBA 尺寸包装、合规扫描或供应链评估 |

内部可使用统一字段：

```json
{
  "verdict": "go | cautious | no-go | need-more-data",
  "confidence": "high | medium | low",
  "key_findings": [],
  "risks": [],
  "action_items": [],
  "missing_inputs": [],
  "next_skill": ""
}
```

## 风险规则

- 不要为了差异化而堆砌无意义功能。
- 不要建议明显侵权、擦边、虚假认证或平台敏感表达。
- 不要只写营销口号；输出必须能被供应商理解并用于打样。
- 不要把“用户喜欢某卖点”直接等同于“值得开发”，必须同时看成本、合规、供应链和 Launch 成本。
- 结论必须区分“观察”“判断”“建议动作”。

## 下一步

- 方案初选后，进入 `profit-cost-estimator` 测算净利率和采购价上限。
- 如果尺寸、包装或套装影响费用，进入 `fba-size-packaging-optimizer`。
- 如果产品涉及敏感属性，进入 `compliance-certification-scanner`。
- 如果需要验证供应商能否落地，进入 `supply-chain-feasibility-review`。
