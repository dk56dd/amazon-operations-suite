# 通用退货分析 Skill 使用文档
Skill 名称：return-analysis

## 一、Skill定位

本 Skill 用于对亚马逊退货数据进行标准化清洗、原因归类、站点对比、产品维度诊断，并输出可复用的退货分析报告。

适用对象：
- 亚马逊多站点退货报告
- 单站点退货报告
- 多 SKU / ASIN / SPU / 父体维度退货分析
- 品类、产品线、系列、变体维度退货诊断
- 退货原因归因与运营整改建议

核心目标：
- 找出退货集中站点
- 找出退货集中产品
- 找出高频退货原因
- 区分产品问题、页面问题、预期管理问题、物流仓储问题
- 形成可执行的 Listing、广告、品控、包装、供应链优化建议

## 二、触发方式

用户可以通过以下表达触发：
- 退货分析
- 生成退货报告
- 退货原因分析
- return analysis
- analyze returns

触发后，读取用户提供的数据文件，不依赖固定本地路径、固定文件名或固定品牌信息。

## 三、输入数据要求

### 1. 支持文件类型

支持以下格式：
- `.xlsx`
- `.xls`
- `.csv`

如文件包含多个工作表，优先识别包含退货字段的工作表；若存在多个有效工作表，需要合并或分别分析，并在报告中说明数据来源。

### 2. 必需字段

| 标准字段 | 是否必需 | 常见别名 | 说明 |
|---|---:|---|---|
| 站点 / 市场 | 是 | site、marketplace、sales-channel、country、store、站点、市场 | 用于区分 US、CA、UK、DE 等销售市场 |
| 产品标识 | 是 | SKU、MSKU、ASIN、SPU、parent SKU、seller-sku、父体、子体 | 用于定位退货产品 |
| 产品名称 | 建议 | product-name、item-name、title、标题、产品名称 | 用于产品类型识别和人工复核 |
| 退货数量 | 是 | quantity、qty、units、return quantity、数量 | 用于统计退货量 |
| 退货原因 | 是 | reason、return reason、buyer reason、原因、退货原因 | 用于原因翻译与归类 |
| 退货状态 | 建议 | status、disposition、resolution、return status、状态 | 用于判断退货处理结果 |
| 日期 | 建议 | date、return-date、request-date、return_date、日期 | 用于周期趋势分析 |

### 3. 可选字段

| 字段 | 用途 |
|---|---|
| order-id / return-id / RMA | 用于去重与追踪 |
| category / product type / collection | 用于产品类型分析 |
| variation / color / size / model | 用于变体维度分析 |
| sales quantity / shipped units | 用于计算退货率 |
| sessions / clicks / orders | 用于联动流量与转化问题 |
| refund amount / item price | 用于计算退货金额影响 |

### 4. 数据口径说明

- 如果只有退货数据，没有销量数据，只输出退货量、退货占比、原因占比，不强行计算退货率。
- 如果同时提供销量数据，则可按站点、SKU、ASIN、SPU、产品类型计算退货率。
- 如果日期字段缺失，则不输出趋势分析，只输出静态汇总。
- 如果退货原因或退货状态出现未知值，保留原始值，并归入“其他 / 未识别”。

## 四、字段标准化规则

系统需要先将原始字段统一映射为以下标准字段：

| 标准字段 | 标准列名 |
|---|---|
| 站点 | marketplace |
| 产品ID | product_id |
| SKU | sku |
| ASIN | asin |
| SPU / 父体 | parent_id |
| 产品名称 | product_name |
| 退货数量 | return_qty |
| 退货原因原文 | raw_reason |
| 退货原因中文 | reason_cn |
| 原因大类 | reason_group |
| 退货状态原文 | raw_status |
| 退货状态中文 | status_cn |
| 日期 | return_date |
| 产品类型 | product_type |

字段映射应通过别名识别完成，不应写死某一种表头格式。

## 五、原因翻译与归类体系

### 1. 常见退货原因中文映射

| 原始原因 | 中文含义 | 原因大类 |
|---|---|---|
| APPAREL_TOO_SMALL | 尺寸 / 容量偏小 | 尺寸与适配问题 |
| APPAREL_TOO_LARGE | 尺寸 / 容量偏大 | 尺寸与适配问题 |
| APPAREL_STYLE | 款式 / 风格不符合预期 | 设计与体验问题 |
| UNWANTED_ITEM | 不想要 / 不再需要 | 购买决策问题 |
| ORDERED_WRONG_ITEM | 买错商品 | 购买决策问题 |
| NOT_AS_DESCRIBED | 与描述不符 | 页面与预期管理问题 |
| DEFECTIVE | 产品有瑕疵 / 损坏 | 产品质量问题 |
| QUALITY_UNACCEPTABLE | 质量不可接受 | 产品质量问题 |
| NOT_COMPATIBLE | 不兼容 / 不适配 | 兼容性问题 |
| DAMAGED_BY_FC | 仓储环节损坏 | 仓储与履约问题 |
| DAMAGED_BY_CARRIER | 物流运输损坏 | 物流与配送问题 |
| FOUND_BETTER_PRICE | 找到更低价格 | 价格与竞争问题 |
| NO_REASON_GIVEN | 未提供原因 | 未说明原因 |

### 2. 通用原因大类

| 原因大类 | 适用判断 |
|---|---|
| 尺寸与适配问题 | 尺寸、容量、规格、型号、安装不匹配 |
| 页面与预期管理问题 | 图片、标题、五点、A+、尺寸图、使用场景表达不准确 |
| 产品质量问题 | 破损、瑕疵、做工、功能失效、质量不可接受 |
| 设计与体验问题 | 款式、手感、使用体验、舒适度、结构设计不满意 |
| 兼容性问题 | 与设备、场景、配件、型号不兼容 |
| 购买决策问题 | 买错、不想要、重复购买、临时取消需求 |
| 价格与竞争问题 | 用户发现更低价格或认为性价比不足 |
| 仓储与履约问题 | FBA 仓储损坏、二次销售状态异常 |
| 物流与配送问题 | 运输损坏、配送延迟、包装保护不足 |
| 未说明原因 | 平台未给出原因或用户未填写原因 |
| 其他 / 未识别 | 规则未覆盖的新原因 |

## 六、产品类型识别规则

产品类型不应绑定固定品牌或固定产品线，应按以下优先级动态识别：

1. 优先使用数据源中的 `category`、`product type`、`collection` 等字段。
2. 如果没有类目字段，则根据 SKU / SPU / 父体前缀识别。
3. 如果 SKU 规则不可用，则根据产品名称关键词识别。
4. 如果仍无法识别，则归入 `Other / 未识别产品类型`。
5. 产品类型规则应放入可配置字典，不应写死在 Skill 主流程中。

建议配置格式：

```yaml
product_type_rules:
  - type: "Backpack"
    keywords: ["backpack", "rucksack", "背包"]
  - type: "Phone Case"
    keywords: ["phone case", "iphone case", "手机壳"]
  - type: "Camera"
    keywords: ["camera", "security camera", "摄像头"]
```

## 七、输出报告结构

默认输出 Excel 报告，也可以同步输出 Markdown 摘要。

### 1. 数据质检

内容：
- 文件名
- 数据行数
- 时间范围
- 识别到的站点数量
- 识别到的产品数量
- 缺失字段检查
- 空值比例
- 重复记录检查
- 未识别原因数量
- 未识别产品类型数量

### 2. 总览 Dashboard

内容：
- 总退货量
- 涉及站点数
- 涉及产品数
- Top 退货原因
- Top 退货产品
- Top 退货站点
- 是否具备退货率计算条件
- 关键风险结论

### 3. 站点汇总

内容：
- 各站点退货量
- 各站点退货占比
- 各站点 Top 原因
- 各站点 Top 产品
- 如有销量数据，输出各站点退货率

### 4. 原因大类分析

内容：
- 原因大类
- 退货量
- 占比
- 涉及产品数
- 主要站点
- 典型产品
- 运营判断
- 优先处理建议

### 5. 原始原因明细

内容：
- 原始原因
- 中文翻译
- 原因大类
- 退货量
- 占比
- 站点分布
- 产品分布

### 6. 产品维度分析

可按以下任一维度输出：
- SKU
- ASIN
- SPU
- 父体
- 产品名称
- 产品类型

内容：
- 产品ID
- 产品名称
- 产品类型
- 退货量
- 退货占比
- Top 退货原因
- Top 站点
- 如有销量数据，输出退货率
- 风险等级
- 动作建议

### 7. 产品类型分析

内容：
- 产品类型
- 退货量
- 占比
- Top 原因
- Top 产品
- 站点分布
- 页面 / 产品 / 供应链优化建议

### 8. 状态分布分析

内容：
- 退货状态原文
- 状态中文
- 数量
- 占比
- 关联原因
- 关联产品
- 对库存、退款、二次销售的影响判断

### 9. 趋势分析

仅在存在日期字段时输出：
- 按日 / 周 / 月退货趋势
- 退货量环比变化
- 主要原因变化
- 异常峰值日期
- 可能关联的广告、促销、价格、物流或 Listing 变更

### 10. 高风险清单

内容：
- 高退货量产品
- 高退货率产品
- 单一原因高度集中的产品
- 特定站点异常产品
- 描述不符集中产品
- 质量问题集中产品
- 物流损坏集中产品

### 11. 运营动作建议

建议按照“问题类型 → 影响 → 优先级 → 动作”输出：

| 问题类型 | 影响 | 优先级 | 建议动作 |
|---|---|---|---|
| 页面与预期管理 | 影响转化与退货率 | 高 | 优化标题、五点、图片、尺寸图、A+、FAQ |
| 产品质量 | 影响评分与账号风险 | 高 | 复盘批次、质检标准、供应商、差评内容 |
| 尺寸与适配 | 影响买家预期 | 中高 | 强化尺寸图、对比图、适配范围、购买前提醒 |
| 物流损坏 | 影响利润与体验 | 中高 | 优化包装、FBA入仓检查、承运链路复盘 |
| 价格竞争 | 影响转化与退货 | 中 | 复盘价格带、优惠券、竞品价格与价值表达 |
| 购买决策 | 影响较弱 | 低中 | 优化目标人群、广告词、场景图与FAQ |

## 八、分析输出原则

1. 先说明数据样本：时间范围、站点数量、产品数量、退货总量。
2. 所有结论必须基于数据，不输出无数据支撑的判断。
3. 优先按“站点 → 产品 → 原因 → 动作”的顺序拆解。
4. 原因分析必须保留原始原因，同时给出中文翻译和大类归因。
5. 如果缺少销量数据，必须明确说明无法计算真实退货率。
6. 如果缺少日期字段，必须明确说明无法判断趋势变化。
7. 如果产品类型无法识别，必须归入“未识别”，不要强行分类。
8. 输出建议要能落到 Listing、广告、品控、包装、物流、库存处理。
9. 避免写入本地路径、本地脚本提示、固定用户目录、固定品牌品类。
10. 不应把某个项目的私有产品线、私有状态样例、私有文件命名写入通用 Skill。

## 九、默认文件命名

建议输出命名：

```text
{source_file_name}_returns_analysis_{YYYYMMDD}.xlsx
{source_file_name}_returns_summary_{YYYYMMDD}.md
```

如果运行环境不支持指定路径，则输出到当前任务目录，并在最终回复中提供文件链接或文件名。

## 十二、通用化边界

本 Skill 不绑定：
- 固定站点
- 固定品牌
- 固定产品类型
- 固定文件名
- 固定本地路径
- 固定子表数量
- 固定数据规模
- 固定运行脚本提示语

所有和业务相关的品类、站点、字段、原因、阈值、产品线，都应通过数据源或配置项动态决定。
