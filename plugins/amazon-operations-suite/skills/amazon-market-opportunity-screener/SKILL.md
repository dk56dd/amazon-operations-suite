# 亚马逊市场机会筛选

## Skill 命名

- 中文名称：亚马逊市场机会筛选
- English Name：Amazon Market Opportunity Screener
- 技能标识：`amazon-market-opportunity-screener`

## 目标

把用户给出的站点、类目、关键词、产品方向或消费场景，转化为可比较、可追溯、可复核的市场机会清单。重点识别蓝海候选、机会市场、未满足需求市场和不建议进入的市场；“蓝海”只能作为基于证据的候选分类，不能被表述为绝对无竞争。

## 触发条件

当用户提到以下任一事项时使用本 Skill：

- 找蓝海市场、机会市场、市场空白或未满足需求；
- 筛选亚马逊站点、类目、子类目、关键词或产品方向；
- 比较多个市场的需求、竞争、增长、价格带或进入难度；
- 根据竞品评论、关键词或市场数据寻找产品机会；
- 要求输出市场机会排名、进入优先级或下一步验证清单。

## 强制数据源门禁

开始任何数据查询、打分或结论前，先向用户明确确认：

> 请确认 `sorftime MCP` 和 `卖家精灵 MCP` 已开启、已授权，并且当前会话可以调用。

只有用户明确确认两者均已开启并可调用后，才能继续。用户回答否、未回答、只确认其中一个、权限不明或连接失败时，立即停止，不得用猜测、旧数据或其他未经授权的数据源替代，也不得输出市场结论。

确认后，先检查当前会话实际暴露的 MCP 工具和参数定义，只调用真实存在的工具；不得凭空编造工具名、字段、指标或接口。若任一数据源仍不可调用，停止并说明缺失项。

## 输入确认

门禁通过后，确认以下范围。缺少会显著改变结论的字段时，先向用户提问并暂停：

| 输入项 | 说明 | 缺失时的处理 |
|---|---|---|
| 亚马逊站点 | 例如美国、英国、日本 | 不得跨站点混用数据，缺失则暂停 |
| 研究范围 | 类目、关键词、ASIN、消费场景或产品方向 | 不能凭空扩大范围 |
| 目标用户 | 使用者、购买者、使用场景和核心痛点 | 影响未满足需求判断 |
| 价格与成本边界 | 目标售价、预计采购成本或毛利底线 | 缺失时只能做需求与竞争初筛 |
| 时间窗口 | 最近 30/90 天、12 个月或其他周期 | 影响趋势和季节性判断 |
| 排除条件 | 受限品、体积重量、认证、供应链等限制 | 纳入筛选和淘汰规则 |

## 数据使用原则

1. 使用 sorftime MCP 获取其实际可提供的市场、关键词、趋势、需求或类目证据；使用卖家精灵 MCP 获取其实际可提供的关键词、竞品、市场规模、产品表现或相关证据。具体字段以当前 MCP 返回的模式为准。
2. 两个来源的口径可能不同。保留原始值、单位、站点、时间范围和提取时间，不直接拼接成一个看似精确的数字；如需合并，先说明口径和换算方法。
3. 每个重要结论都要附证据记录：数据源、MCP 工具、查询条件、时间窗口、返回字段、提取时间和数据限制。无法追溯的数据不得进入核心评分。
4. 评论、关键词或竞品数据只支持“可能存在需求缺口”，不等于已验证的产品需求。必须把缺口转化为可验证的用户问题、功能假设或产品规格。
5. 不得把搜索量、销售额、增长率或竞争度填成估算值而不标注；如果 MCP 未返回某字段，显示“未提供”，不要补数。
6. 需要保存历史研究结果时，默认使用 PostgreSQL；保存原始快照和标准化结果，禁止用临时表格覆盖唯一事实来源。未得到用户授权时只在报告中输出，不写入数据库。

## 执行流程

### 1. 建立研究口径

记录站点、类目层级、关键词语言、币种、时间窗口、样本范围、去重规则和排除条件。先定义什么叫“值得进入”，再收集数据，避免为了迎合结论而调整指标。

### 2. 采集并标准化

分别从两个 MCP 取得可用数据，并生成来源清单。统一站点、币种、时间窗口和产品标识；处理重复 ASIN、变体拆分、品牌店铺混入、明显异常值和缺失值。任何清洗都记录规则和影响范围。

### 3. 建立市场维度

至少从以下维度评价；可用字段不足时降低数据置信度，不得伪造完整性：

| 维度 | 关注问题 | 典型证据 | 优势 | 劣势 |
|---|---|---|---|---|
| 需求强度 | 是否有人稳定搜索和购买 | 搜索需求、销售表现、关键词覆盖 | 能判断市场是否有真实流量 | 容易受季节、站点和数据口径影响 |
| 需求趋势 | 需求是在增长、稳定还是衰退 | 时间序列、同比或环比变化 | 能识别早期增长机会 | 短周期波动可能造成误判 |
| 竞争压力 | 头部集中度和进入门槛如何 | 头部产品、评论量、品牌集中、广告竞争 | 能估计争夺流量的难度 | 公开指标不能完整反映供应链和品牌壁垒 |
| 用户缺口 | 用户是否反复表达不满或未被满足 | 评论主题、差评痛点、功能缺口、场景缺失 | 能把市场数据转成产品假设 | 评论存在偏差，不能代替访谈和样品验证 |
| 经济性 | 价格、成本和费用后是否可能盈利 | 价格带、费用、物流、退货和成本边界 | 能避免只看需求不看利润 | 成本信息常来自用户输入或后续报价 |
| 进入约束 | 是否有认证、专利、受限品或物流限制 | 用户约束、类目规则、风险初筛 | 可提前剔除不适合方向 | 本 Skill 不替代法律、认证或平台官方确认 |

### 4. 识别市场类型

使用“证据 + 置信度 + 待验证事项”而不是单一标签：

| 市场类型 | 判定特征 | 不应忽略的风险 | 输出建议 |
|---|---|---|---|
| 蓝海候选 | 需求证据明确，竞争相对分散，存在可描述且可解决的用户缺口 | 可能是数据覆盖不足、需求过小或进入壁垒尚未暴露 | 列为高潜候选，必须安排样品、成本和合规验证 |
| 机会市场 | 需求和经济性较好，但竞争或进入约束中等 | 可能需要差异化、内容、渠道或供应链能力 | 列为可验证候选，给出进入条件 |
| 未满足市场 | 用户痛点重复且明确，但现有供给没有有效解决 | 痛点未必愿意付费，解决成本可能高 | 先验证愿付价格和产品可行性 |
| 红海/谨慎市场 | 头部集中、竞争强、差异化弱或单位经济性不足 | 可能需要高投放、高库存和品牌投入 | 默认不优先，除非用户有明确资源优势 |
| 数据不足市场 | 关键数据缺失、口径冲突或样本不可靠 | 结论容易成为伪精确 | 暂不排名，列出补数方案 |

### 5. 评分与排序

可使用 100 分制，但必须展示权重、原始指标、标准化方法、数据置信度和扣分原因。默认框架如下，用户指定权重时以用户为准：

| 评分项 | 默认权重 | 评分含义 | 优势 | 劣势 |
|---|---:|---|---|---|
| 需求吸引力 | 30% | 需求规模、稳定性和增长 | 直接反映市场天花板 | 高需求也可能伴随高竞争 |
| 竞争可进入性 | 25% | 竞争压力的反向分 | 体现新卖家切入难度 | 竞争数据不一定覆盖线下和站外品牌 |
| 用户缺口强度 | 20% | 痛点频率、明确性和可解决性 | 有助于形成差异化 | 需要进一步做产品验证 |
| 经济性 | 15% | 价格带、成本边界和费用后的潜力 | 防止只追求销量 | 早期成本可能不准确 |
| 数据置信度 | 10% | 样本量、来源一致性和时效性 | 让不确定性显性化 | 不能替代商业判断 |

若数据置信度低于预设门槛，降低排名或标记为“待补数”，不得仅因其他分数高而推荐进入。

### 6. 形成决策建议

为每个候选市场写出：机会假设、关键证据、主要优势、主要劣势、淘汰条件、需要补充的数据、最小验证动作和建议负责人。不要只给一个总分；用户需要知道“为什么值得验证”和“验证失败时何时止损”。

## 固定输出格式

始终按以下结构输出中文报告；所有数据展示和横向比较使用表格，并同时写清优势与劣势：

1. **数据源门禁**：用户确认原文、两个 MCP 的可用状态、实际调用工具、失败项。
2. **执行摘要**：优先推荐、谨慎观察、暂不进入；每项给一句结论和置信度。
3. **研究口径**：站点、范围、时间、币种、样本、假设和排除条件。
4. **候选市场对比表**：需求、趋势、竞争、缺口、经济性、风险、置信度、优势、劣势和排名。
5. **机会证据表**：每个市场对应的用户痛点、证据来源、可做产品假设和证据局限。
6. **淘汰与降级清单**：说明被淘汰或降级的原因，不能只列结果。
7. **下一步验证计划**：样品、成本、合规、关键词、小预算测试、成功指标、截止条件。
8. **数据附录**：调用时间、查询条件、字段口径、缺失字段、清洗规则和数据置信度。

## 停止条件与错误处理

- 两个 MCP 未经用户明确确认：停止。
- 任一 MCP 不可调用、权限失效或返回空结果：停止核心分析，说明如何恢复，不得用替代数据填充。
- 关键字段缺失或两个来源口径无法对齐：输出“数据不足”，不输出确定性推荐。
- 用户要求直接断言“绝对蓝海”“绝无专利”或“稳赚”：拒绝这种表述，改为证据边界和验证方案。
- 涉及专利、认证或法律结论：仅提示初筛风险，转交对应专业核验，不把市场筛选结果当作法律意见。

## 并发和审计要求

并发 MCP 查询不超过 5 个；优先按站点或数据类型分组，避免无边界批量调用。每次运行保留研究编号、用户输入摘要、数据源、时间、查询参数、输出版本和人工确认节点，便于复盘和企业级审计。
