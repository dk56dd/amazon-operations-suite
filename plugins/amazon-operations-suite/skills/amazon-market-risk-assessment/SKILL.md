# 亚马逊市场进入风险评估

## Skill 命名

- 中文名称：亚马逊市场进入风险评估
- English Name：Amazon Market Entry Risk Assessment
- 技能标识：`amazon-market-risk-assessment`

## 目标

在亚马逊产品立项、市场进入或扩大投入前，系统识别竞品、市场、知识产权、认证法规、平台、供应链、财务和运营风险，并给出可执行的缓解措施、责任人、时限和继续/暂停/停止条件。本 Skill 只做基于证据的经营与合规初筛，不替代律师、专利代理师、认证机构、海关或平台官方裁定。

## 触发条件

出现以下任一请求时使用本 Skill：

- 评估一个产品或类目能不能做、风险大不大；
- 查看竞品壁垒、市场饱和、价格战、跟卖或集中度风险；
- 做专利、商标、外观、版权或知识产权初筛；
- 判断认证、法规、材料、功能宣称、标签或进口要求；
- 输出新品立项风险清单、风险矩阵、尽调报告或 Go/No-Go 建议；
- 在备货或投放前要求确认主要风险和止损条件。

## 强制数据源门禁

在任何查询、分析和评分前，必须先向用户明确询问：

> 请确认 `sorftime MCP` 和 `卖家精灵 MCP` 已开启、已授权，并且当前会话可以调用。

只有用户明确确认两者均可用后才可继续。未确认、只确认一个、权限不明、调用失败或结果不可访问时，立即停止，不得用记忆、猜测或虚构数据补足。

确认后，检查当前会话实际提供的工具和字段，只使用真实存在的 MCP 能力。sorftime MCP 与卖家精灵 MCP 主要用于市场、关键词、竞品和产品表现证据；它们不天然等同于专利、认证或法律官方数据库。若当前没有官方专利/商标/法规来源或用户提供的正式文件，相关结论必须标注“未核验”，并按较高风险处理。

## 输入确认

开始评估前收集下表信息。若缺少产品身份、目标站点或目标国家，暂停核心结论，因为不同站点和国家可能适用不同规则。

| 输入项 | 需要确认的内容 | 缺失处理 |
|---|---|---|
| 产品身份 | 产品名称、结构、材质、功能、尺寸、配件、图片或草图 | 无法准确做竞品与 IP 范围时暂停 |
| 目标市场 | 亚马逊站点、销售国家、进口国家、目标人群 | 不得用一个国家的法规推断另一个国家 |
| 功能宣称 | 医疗、儿童、安全、环保、食品接触、防护、功效等表述 | 宣称不明时按高风险处理 |
| 价格与成本 | 目标售价、采购价、物流、平台费用和毛利目标 | 只能评估非财务风险 |
| 供应链 | 供应商、制造地、原材料、MOQ、交期和质量文件 | 缺失时提高供应链风险等级 |
| 已有文件 | 检测报告、认证证书、专利/商标检索、合同、保险 | 只接受可核验文件，不接受口头承诺 |
| 竞争边界 | 竞品 ASIN、关键词、品牌、类目或相似产品 | 缺失时使用 MCP 可验证范围，并注明样本边界 |

## 风险分类与证据边界

至少覆盖以下风险，并给出优势与劣势，避免只列风险而没有判断依据：

| 风险类别 | 要回答的问题 | 主要证据 | 优势 | 劣势/边界 |
|---|---|---|---|---|
| 竞品风险 | 头部集中、价格战、评论壁垒、品牌壁垒和跟卖压力如何 | sorftime MCP、卖家精灵 MCP 的实际返回数据 | 能量化市场结构和竞争强度 | 不能完整观察私域、线下和未公开供应链 |
| 市场风险 | 需求是否季节性、衰退、过度依赖单一关键词或站点 | 市场趋势、关键词和产品表现证据 | 可识别需求波动和市场天花板 | 历史趋势不保证未来表现 |
| 专利/商标/外观风险 | 产品结构、外观、命名、包装或宣称是否可能侵权 | 官方检索、用户正式资料、专业意见 | 能提前发现高代价风险 | MCP 市场数据不能证明“不侵权”，未检索不等于没有权利 |
| 认证法规风险 | 是否需要测试、认证、标签、警示、注册或进口文件 | 目标国家官方要求、认证机构文件、用户资料 | 可把要求转成办理清单 | 不同用途、材料和宣称可能改变要求 |
| 平台合规风险 | 类目审核、限制品、图片文案、评价和知识产权政策是否有风险 | 平台规则、用户已有通知和产品资料 | 能避免上架后下架或冻结 | 平台规则会变化，必须记录核验日期 |
| 供应链风险 | 质量、交期、MOQ、替代供应商和批次一致性如何 | 供应商文件、样品和订单历史 | 可提前设计备选和抽检 | 纸面文件不能代替批量质量验证 |
| 财务风险 | 现金占用、费用、退货、广告和汇率变化是否可承受 | 用户预算、成本、费用和情景假设 | 便于设定止损线 | 早期销量和费用通常存在不确定性 |
| 运营风险 | 客服、售后、仓储、内容和广告能力是否匹配 | 团队能力、流程和历史数据 | 能发现执行能力缺口 | 需要结合企业内部资源判断 |

## 执行流程

### 1. 建立产品与管辖范围

把产品拆成结构、材料、功能、接触对象、使用场景、宣称、包装和销售渠道。明确评估的是“进入某站点的初筛”还是“准备实际上市”，两者的证据深度不同。

### 2. 采集市场和竞品证据

门禁通过后，分别调用两个 MCP 的实际可用工具。记录查询范围、样本量、时间窗口、站点和字段口径。重点检查：头部集中度、价格带、评论和评分壁垒、广告/关键词依赖、同质化程度、产品缺口和异常竞争信号。

### 3. 做知识产权初筛

不要把竞品数量、产品页面或关键词数据当成专利检索。按产品名称、功能、结构、外观、包装、商标名称和目标国家拆检索范围。对每个未获得官方或专业证据的项目标记：

- 状态：未核验；
- 风险：不降低；
- 需要的证据：官方数据库检索、权利要求比对、商标类别检索或专业意见；
- 决策：在核验前不得做大额备货或不可逆模具投入。

### 4. 做认证与法规初筛

按目标国家、用途、用户群、接触材料、供电方式、无线功能、儿童属性、健康或安全宣称逐项检查。把“需要认证”“需要测试”“需要标签/文件”“需专业确认”分开，不把营销语言当作法定分类。没有正式要求或报告时，不得输出“无需认证”。

### 5. 量化风险

采用概率与影响的 5×5 矩阵，并单独保留证据置信度：

| 分值 | 概率定义 | 影响定义 | 处理 |
|---:|---|---|---|
| 1 | 目前证据显示很少发生 | 对成本、进度和账号影响很小 | 例行监控 |
| 2 | 有可能但证据较弱 | 可通过常规流程吸收 | 指定负责人 |
| 3 | 中等可能或证据冲突 | 会影响上市或利润 | 上市前关闭关键事项 |
| 4 | 较可能或已有预警 | 可能造成大额损失、下架或召回 | 暂停相关投入并验证 |
| 5 | 已发生、强信号或证据缺失却后果严重 | 可能导致侵权、禁售、召回、账户或现金流重大损失 | 默认停止，取得正式证据后再评估 |

风险分数 = 概率 × 影响。分数只能帮助排序，不能覆盖硬性红线；专利、认证、产品安全和平台禁售类事项即使概率尚未确认，也不得按低风险处理。

### 6. 输出决策

给出三种结论之一：

- **继续验证**：没有未关闭的硬性红线，且关键假设有明确验证计划；
- **限额试验**：存在中高风险，但可通过小批量、可退供应链或低不可逆成本方式验证；
- **暂停/停止**：存在未核验的重大 IP、认证、产品安全、平台禁售、现金流或无法缓解的结构性风险。

## 固定输出格式

始终用中文，数据和比较使用表格，并同时展示优劣势：

1. **门禁结果**：用户确认内容、两个 MCP 实际可用状态、不可用工具和影响。
2. **执行摘要**：总判断、决策等级、三项最高风险、立即动作。
3. **产品与管辖范围**：产品拆解、站点、国家、用途、宣称和假设。
4. **竞品与市场风险表**：指标、证据、判断、优势、劣势、置信度和数据局限。
5. **IP 初筛表**：对象、目标国家、已查范围、证据、风险、未决问题、专业核验动作。
6. **认证法规表**：适用性、所需文件/测试、证据状态、负责人、截止时间和未完成后果。
7. **综合风险矩阵**：类别、风险描述、概率、影响、分数、证据、缓解措施、责任人和关闭条件。
8. **Go/No-Go 清单**：继续、限额试验、暂停或停止的具体判定条件。
9. **验证计划**：按优先级、成本、耗时、依赖和止损点排序。
10. **证据附录**：MCP 工具、查询参数、时间、官方链接或文件、版本和数据缺口。

## 强制防错规则

- 不得说“没有专利”“无需认证”“一定合规”“不会被跟卖”或“低风险”而没有对应范围、日期和证据。
- 不得把市场份额或竞品数据解释为法律权利结论。
- 对来源冲突保留两个值，解释冲突原因，不擅自取对自己有利的值。
- 不得因为用户希望快速上架而跳过硬性风险核验。
- 用户要求实际购买、上架、投放或联系供应商时，本 Skill 只提供风险决策依据；除非用户另行明确授权，不执行外部不可逆操作。

## 并发和审计要求

并发 MCP 查询不超过 5 个。保存研究编号、产品版本、目标站点、用户确认节点、数据快照、证据时间、风险评分版本和人工决策结果；需要持久化时默认使用 PostgreSQL，不使用其他数据库替代。
