# 市场切入度判断

## 核心原则

先判断数据接入，再判断市场机会。不要在缺少 MCP 数据时伪装成高精度结论。

本 Skill 适用于亚马逊市场切入判断，包括类目调研、关键词机会、竞品格局、产品进入难度、推广 ROI、供应链适配和上架策略建议。

## 第 0 步：MCP 接入检查

开始分析前必须先判断当前 agent 是否能调用以下 MCP 或等效工具：

- `sorftime mcp`
- `sif mcp`
- `卖家精灵 mcp` / `sellersprite mcp`

检查方式：

- 若当前会话已暴露 MCP 工具，直接检查可调用工具名称和能力。
- 若支持 `tool_search`，优先搜索 `sorftime`、`sif`、`sellersprite`、`卖家精灵`。
- 不要编造未暴露的 MCP 工具名；只能调用当前真实可用的工具。

按检查结果分流：

- 三类 MCP 均不可用：先告诉用户“当前未检测到 sorftime / SIF / 卖家精灵 MCP 接入，下面只能调用联网公开数据做初步判断，类目销量、关键词份额、广告成本、竞品销量会有明显误差”。然后使用 Web / 官方公开页 / Amazon 前台可见信息做低置信分析。
- 只有部分 MCP 可用：说明已接入和缺失的数据源，继续分析，但必须在结论里标注缺口和置信度。
- MCP 可用：进入 MCP 数据链路，不要优先用泛搜索替代 MCP 数据。

## 第 1 步：识别用户输入类型

根据用户输入选择主路径：

- 类目 / 赛道：例如“这个类目能不能做”“想进这个赛道”。
- 关键词：例如“这个词值不值得打”“关键词有没有机会”。
- 产品 / ASIN：例如“这个产品能不能做”“这个竞品我能不能打”。
- 供应链想法：例如“1688 上这个货能不能做亚马逊”。
- 混合问题：先拆成类目机会、竞争强度、ROI 三个判断。

若信息不足，最多问 3 个关键问题：

- 站点：默认 US，用户指定则按指定站点。
- 目标价格带 / 成本 / 毛利要求。
- 已有产品、ASIN、关键词或供应链链接。

不要因为信息不足停止所有工作；可先做“基于现有输入的初判”。

## 第 2 步：MCP 优先数据链路

### SIF MCP 可用时

先定位三大问题，再调用入口工具：

- 赛道有没有机会：先用 `market_evaluate_niche`。
- 我能不能竞争：先用 `market_analyze_competition`。
- 这个词推广能不能赚钱：先用 `market_assess_keyword_promotion`。

使用规则：

- 用户问类目/赛道，先做赛道层判断，再从工具返回的高流量关键词下钻到单词层。
- 用户问竞品/怎么打，先看竞争格局，再看头部 ASIN、集中度、评价门槛、价格带。
- 用户问广告/ROI，先看关键词推广可行性，再估算 CPC、转化率、售价、毛利空间。
- 不要跳过赛道层，直接用随机关键词判断整个市场。

### 卖家精灵 MCP 可用时

优先用于验证：

- ASIN 销量、销售额、价格、BSR、类目排名。
- 评论数量、评分、差评集中点。
- 竞品趋势、季节性、上架时间、品牌集中度。
- 关键词或类目下的产品分布。

输出时把卖家精灵结果用于“竞争强度”和“进入门槛”，不要只复述销量。

### sorftime MCP 可用时

优先用于：

- 类目树和节点定位。
- 类目下产品池、价格带、销量区间、排名数据。
- 关键词和商品维度的交叉验证。

若 sorftime 与卖家精灵/SIF 数据不一致，说明口径差异，并用更贴近用户问题的维度作为主证据。

## 第 3 步：无 MCP 时的联网兜底

若未检测到 MCP，必须先输出风险提示：

```text
当前未检测到 sorftime / SIF / 卖家精灵 MCP 接入。下面只能调用联网公开数据做初步判断，类目销量、关键词份额、广告成本、竞品销量会有明显误差，结论只能作为方向筛选，不适合作为最终投产依据。
```

联网兜底可用数据：

- Amazon 前台搜索结果、BSR、评价数、价格、卖点表达。
- 品牌官网、竞品官网、公开测评。
- Google Trends、TikTok/YouTube/Reddit 等公开需求信号。
- Keepa/第三方公开页面仅在可访问时作为辅助，不要编造付费数据。

无 MCP 时不得输出以下高精度结论：

- 精确月销量、精确销售额、精确关键词份额。
- 精确 PPC CPC、ACOS、转化率。
- “一定能做 / 一定不能做”的绝对判断。

## 第 4 步：统一判断框架

每次市场切入判断至少覆盖 7 个维度：

1. 需求强度：搜索量、销量、排名、趋势、季节性。
2. 竞争强度：头部集中度、评论门槛、品牌垄断、价格带拥挤度。
3. 差异化空间：功能、材质、套装、场景、人群、合规认证、内容表达。
4. 利润空间：售价、成本、FBA/物流、退货风险、广告承受力。
5. 推广难度：关键词 CPC、广告位、自然排名爬坡、内容转化要求。
6. 供应链适配：起订量、交期、质检、包装、专利/认证、售后风险。
7. 切入路径：先测款、避开头部词、细分人群、组合包、价格策略。

## 第 5 步：输出结构

第一句话必须直接给判断：

```text
这个市场当前适合/不适合/谨慎切入，原因是……
```

推荐输出格式：

```markdown
这个市场当前【适合 / 谨慎 / 不建议】切入，核心原因是……

**证据**
- 需求：……
- 竞争：……
- 利润：……
- 推广：……
- 供应链：……

**切入建议**
- 切入人群/场景：……
- 首批 SKU：……
- 价格带：……
- 广告起手词：……
- 避开的坑：……

**置信度**
- 数据来源：……
- 数据缺口：……
- 把握程度：高 / 中 / 低

**下一步**
- A. 做关键词级 ROI 测算
- B. 做竞品 ASIN 拆解
- C. 做供应链成本核算
```

## 第 6 步：结论口径

使用三档结论，不要模糊：

- `适合切入`：需求明确、竞争可拆、利润可覆盖广告、供应链风险可控。
- `谨慎切入`：有需求但竞争/利润/供应链存在明显短板，需要先测小切口。
- `不建议切入`：头部垄断强、评价门槛高、利润无法覆盖广告，或存在合规/专利高风险。

必须解释“为什么不是另一个结论”。例如：

- 不是不能做，而是不适合直接打大词。
- 不是需求不足，而是评论门槛和广告成本太高。
- 不是供应链没有机会，而是当前规格不匹配 Amazon 主流价格带。

## 第 7 步：质量红线

- 不要在没有 MCP 或可靠公开数据时编造销量、销售额、CPC。
- 不要只给泛泛建议，必须给可执行切入动作。
- 不要把“类目机会”和“单个关键词机会”混为一谈。
- 不要忽略合规、专利、退货和差评风险。
- 不要默认 US 以外站点；用户未指定时默认 US。
- 如果 MCP 工具报错，说明错误类型，降级到联网兜底，并降低置信度。
