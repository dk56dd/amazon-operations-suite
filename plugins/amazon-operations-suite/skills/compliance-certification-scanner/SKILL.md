# 合规与认证风险扫描 Skill

中文名称：合规与认证风险扫描  
English name: `compliance-certification-scanner`

## 使用目标

帮助用户在新品开发前识别上架、认证、测试、标签、说明书和 Listing 宣称风险，避免产品开发后才发现无法销售或成本失控。

## 触发场景

在以下情况使用本 skill：

- 用户准备开发新品，需要判断能不能上架、要不要认证。
- 用户问“这个产品美国能卖吗”“欧洲需要什么认证”。
- 产品涉及儿童、母婴、食品接触、皮肤接触、带电、电池、无线、医疗健康、化妆品、化学品、个人防护等敏感属性。
- 用户想检查 Listing 宣称是否有风险。

不适合使用本 skill 的情况：

- 用户只想做利润测算，应使用 `profit-cost-estimator`。
- 用户只想做供应商报价对比，应使用 `supply-chain-feasibility-review`。
- 用户没有站点时，只能做通用风险识别，不得输出确定认证要求。

## 必需输入

- `marketplace`：具体站点，例如 US、CA、UK、DE、JP；没有站点不得输出确定认证要求。
- `product_type`：产品类型。
- `materials`：材质。
- `target_user`：目标人群。
- `usage_scenario`：使用场景。
- `electrical_or_battery`：是否带电、带电池、充电或无线。
- `food_contact`：是否接触食品。
- `children_related`：是否儿童、母婴或玩具相关。
- `claims`：Listing 或包装上计划使用的宣称。

## 可选数据源

- 类目、竞品 ASIN、供应商已有证书、包装标签、说明书、测试报告。
- 官方政策、法规页面、认证机构资料。高风险或政策可能变化时，优先核验官方来源。

## 数据要求

分析前先做数据完整性检查，并在输出开头写清“已满足 / 缺失 / 只能通用风险识别”。

| 数据项 | 最低要求 | 缺失时处理 |
|---|---|---|
| 站点 | 必须提供具体站点，例如 US、CA、UK、DE、JP | 没有站点只能做通用风险识别，不得输出确定认证要求 |
| 产品类型 | 具体产品名和用途 | 无法判断类目合规 |
| 材质 | 主要接触材质、包装材质、涂层 | 不能判断食品接触、皮肤接触、化学风险 |
| 目标人群 | 成人、儿童、母婴、宠物等 | 不能判断儿童/母婴敏感要求 |
| 使用场景 | 室内、户外、车载、厨房、身体接触等 | 不能判断标签和警告要求 |
| 敏感属性 | 是否带电、电池、无线、食品接触、皮肤接触、儿童相关 | 缺失时必须逐项追问 |
| Listing 宣称 | 防水、杀菌、无毒、环保、医疗、认证等表达 | 无宣称时只能提醒常见高风险表达 |

合规判断必须基于具体站点和产品属性；没有站点时不得输出“需要某认证”的确定结论。

## MCP / 官方核验约束

- 本 skill 不强制 Sorftime 或卖家精灵 MCP；合规高风险或政策可能变化时，优先使用官方政策、官方法规或认证机构资料核验。
- 如用户要求用 MCP 获取竞品 ASIN、类目、Listing 宣称或证书线索，必须先确认相关 MCP 已开启。
- MCP 未开启时，不要编造竞品类目、证书、测试报告或平台审核要求。
- 官方政策无法核验时，必须标注“待官方政策或认证机构确认”，不要输出最终法律判断。
- 供应商证书只能作为线索，必须核验证书主体、型号、标准、有效期、适用站点和产品一致性。

## 工作流

1. 先做数据完整性检查和 MCP/官方核验来源检查；没有具体站点时只输出通用风险识别。
2. 确认站点、类目、产品用途、材质、人群和敏感属性。
3. 按站点判断基础合规要求，并标注数据口径和不确定项。
4. 扫描敏感属性：儿童、母婴、食品接触、带电、电池、医疗健康、化妆品、化学品、无线、个人防护。
5. 检查 Listing 宣称风险：治疗、杀菌、防火、防水、环保、无毒、认证标识等。
6. 输出所需认证、测试报告、标签、说明书、警告语和供应商必须提供的文件。
7. 标注上架前必须确认项，以及需要官方政策或认证机构确认的高风险点。

## 输出合同

用中文输出。涉及不同站点或认证路径对比时必须用表格，并说明优劣势。必须包含：

| 模块 | 必填内容 |
|---|---|
| 数据状态 | 已用数据、MCP/官方核验状态、缺失字段、站点口径 |
| 合规风险等级 | 低、中、高、禁止/极高 |
| 站点适用性 | 当前站点是否可初步开发，哪些条件待确认 |
| 所需认证/测试 | 认证、测试报告、标签、说明书、警告语 |
| Listing 禁用或谨慎表达 | 不能写、谨慎写、需要证据支撑的表达 |
| 供应商文件清单 | 证书、报告、材质声明、标签图、说明书、生产信息 |
| 上架前检查清单 | 开发前、打样后、发货前、上架前要确认的事项 |
| 缺失输入 | 影响判断的站点、材质、用途、人群、宣称、报告 |
| 下一步 skill | 利润测算、供应链评估或差异化方案调整 |

内部可使用统一字段：

```json
{
  "verdict": "go | cautious | no-go | need-more-data",
  "confidence": "high | medium | low",
  "key_findings": [],
  "risks": [],
  "action_items": [],
  "missing_inputs": [],
  "next_skill": ""
}
```

## 风险规则

- 合规结论必须标注“非法律意见”。
- 没有具体站点时不得输出确定认证要求。
- 高风险产品应建议查官方政策或专业认证机构，不要装作最终法律判断。
- 不要建议规避认证、绕开平台审核或使用虚假认证标识。
- 不要把供应商提供的证书截图直接当作有效证书，必须要求核验证书主体、型号、标准、有效期和适用站点。

## 下一步

- 如果合规风险低或中，进入 `profit-cost-estimator` 将认证和测试费用纳入利润模型。
- 如果需要供应商提供证书或测试报告，进入 `supply-chain-feasibility-review`。
- 如果某个差异化功能带来高合规风险，返回 `product-differentiation-planner` 调整方案。
