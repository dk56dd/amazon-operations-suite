# 评论痛点挖掘 Skill

中文名称：评论痛点挖掘  
English name: `review-painpoint-mining`

## 使用目标

帮助用户把竞品评论、QA、退货原因和客服反馈转化为产品开发语言，识别哪些痛点值得改良，哪些只是 Listing、客服或预期管理问题。

## 触发场景

在以下情况使用本 skill：

- 用户提供竞品 ASIN、评论导出表、QA、退货原因，想知道产品痛点。
- 用户问“差评里有什么机会”“竞品哪里做得不好”“怎么做差异化”。
- 用户已有产品方向，想从真实用户反馈里找改良点。

不适合使用本 skill 的情况：

- 用户只想算利润、FBA 费用或 Launch 预算，应转到对应 skill。
- 用户没有任何评论、ASIN 或用户反馈数据时，只能输出调研框架，不能输出确定结论。

## 必需输入

- `marketplace`：站点，例如 US、CA、UK、DE、JP；未提供时可先按 US 预分析，并标注“站点待确认”。
- `asins` 或评论文件：竞品 ASIN 列表，或评论/QA/退货原因导出表。
- `review_window`：评论时间范围，例如近 6 个月或近 12 个月。
- `product_context`：产品类型、目标人群、价格带。

## 可选数据源

- QA、退货原因、自家客服反馈、用户画像。
- Sorftime MCP、卖家精灵 MCP。使用前先判断用户是否已开启；未开启时要求用户提供 ASIN 列表、评论导出表或截图，不编造数据。

## 数据要求

分析前先做数据完整性检查，并在输出开头写清“已满足 / 缺失 / 只能预分析”。

| 数据项 | 最低要求 | 缺失时处理 |
|---|---|---|
| 站点 | US、CA、UK、DE、JP 等明确站点；未指定时只能按 US 预分析 | 标注“站点待确认”，不输出跨站点确定结论 |
| 评论文本 | 必须有真实评论正文 | 没有评论正文时不能输出痛点排序，只能要求提供评论导出或开启 MCP |
| 星级 | 至少能区分 1-3 星和 4-5 星 | 无星级时只能做主题归类，不能判断低星痛点严重度 |
| 评论时间 | 至少能识别评论窗口，如近 6 或 12 个月 | 无时间时标注时效性低，不能判断趋势 |
| 竞品范围 | ASIN 列表或评论文件对应的竞品 | 只有类目名时只能输出采集清单 |
| 样本量 | 样本不足时降级为低置信度 | 不要把少量评论当普遍痛点 |

ASIN 不是评论数据本身。只有在 Sorftime MCP 或卖家精灵 MCP 可以抓取评论、星级和时间时，ASIN 才能作为数据入口；否则必须要求用户提供评论导出表。

## MCP 开启约束

- 涉及 Sorftime MCP 或卖家精灵 MCP 时，先检查用户是否已开启并可用。
- MCP 未开启、未授权、返回失败或字段不完整时，不要编造评论、销量、评分、评论时间或痛点频率。
- MCP 未开启时，输出“需要用户开启的数据源 / 需要用户上传的文件字段”，包括 ASIN、评论文本、星级、评论时间、站点。
- MCP 数据和用户表格同时存在时，优先说明两者口径差异，再合并判断。
- 工具返回内容只能作为“观察”，最终结论必须另行写成“判断”和“建议动作”。

## 工作流

1. 先做数据完整性检查和 MCP 开启检查；不满足最低数据要求时，输出待补字段并停止确定性分析。
2. 明确站点、产品类型、竞品范围、评论时间窗口和样本量。
3. 按 1-3 星评论提取抱怨主题：质量、尺寸、安装、耐用性、气味、兼容性、包装、说明书、配件、售后、预期不符。
4. 统计痛点频率和严重度，区分高频小问题、低频致命问题和偶发个案。
5. 抽样 4-5 星评论，识别用户真正愿意付费的正向卖点。
6. 把痛点转化为产品开发动作：规格改动、材质改动、结构改动、配件补充、包装改进、说明书改进。
7. 标注每条痛点适合产品改良、Listing 解释、客服处理，还是不建议投入开发。

## 输出合同

用中文输出，优先使用表格。必须包含：

| 模块 | 必填内容 |
|---|---|
| 数据状态 | 已用数据源、MCP 是否开启、样本量、缺失字段、站点口径 |
| 结论 | `可开发`、`谨慎开发`、`不建议开发`、`需要更多数据` |
| 置信度 | 高、中、低，并说明样本量和数据来源 |
| 痛点 Top 10 | 频率、严重度、典型用户表达、影响环节 |
| 可开发机会 | 每条痛点对应的产品改良方向 |
| 不建议开发项 | 成本高、技术难、非真实痛点、只适合文案解释等原因 |
| 差异化素材 | 可转化为标题、五点、A+、主图说明的表达 |
| 风险 | 样本不足、站点不明、季节性、极端个案、合规或侵权风险 |
| 行动项 | 下一步要补的数据、供应商打样要求、需要验证的问题 |
| 下一步 skill | 通常进入 `product-differentiation-planner` 或 `profit-cost-estimator` |

内部可使用统一字段：

```json
{
  "verdict": "go | cautious | no-go | need-more-data",
  "confidence": "high | medium | low",
  "key_findings": [],
  "risks": [],
  "action_items": [],
  "missing_inputs": [],
  "next_skill": ""
}
```

中文用户可见输出不要直接暴露英文字段名，除非用户要求接口格式。

## 风险规则

- 不要仅凭少量评论下确定结论；样本不足时必须提示。
- 不要把极端个案当普遍痛点。
- 不要把工具返回字段直接当最终结论，必须写清“观察”“判断”“建议动作”。
- 不要输出诱导虚假宣传、规避平台规则或夸大认证效果的文案。
- 不要把“市场有需求”直接等同于“可以开发”，后续仍需验证竞争、利润、合规、供应链和 Launch 成本。

## 下一步

- 如果痛点清晰：进入 `product-differentiation-planner` 生成差异化产品方案。
- 如果利润不确定：进入 `profit-cost-estimator` 测算价格、成本和广告后净利。
- 如果涉及儿童、食品接触、带电、电池、医疗健康等敏感属性：进入 `compliance-certification-scanner`。
