# 新闻与产品影响分析 Skill / News & Product Impact Analysis Skill

## 技能命名

| 语言 | 名称 | 用途 |
|---|---|---|
| 中文名 | 新闻与产品影响分析 | 面向中文使用者，分析新闻、趋势、政策、平台变化对产品经营结果的影响 |
| English name | News & Product Impact Analysis | For assessing how news, events, trends, policies, or market signals affect a product, ASIN, category, brand, advertising, or selection decision |

## 使用目标

使用本技能时，先把“新闻本身是否真实、是否新、是否与产品相关”查清楚，再判断它会怎样影响产品。分析对象可以是亚马逊 ASIN、独立站产品、跨境电商产品、品牌、类目、竞品、供应链节点、广告计划或选品机会。

本技能的重点不是复述新闻，而是把新闻转化为可执行的经营判断：是否会影响需求、转化率、广告成本、自然排名、关键词搜索量、供应链、价格、库存、合规风险、类目竞争、评价舆情和进入/退出时机。

## 触发场景

当用户提出以下需求时使用本技能：

- “这条新闻对我的产品有什么影响？”
- “这个政策/平台规则/行业变化会不会影响某个 ASIN？”
- “帮我分析某个产品最近受新闻影响的风险和机会。”
- “某个事件会不会影响亚马逊广告投放、关键词、竞价或预算？”
- “根据最近新闻判断这个产品还能不能做。”
- “竞品、品牌、类目、供应链、法规、舆情有变化，分析对产品的影响。”
- “做一份新闻和产品影响分析报告。”

不要在用户只要求普通新闻摘要、纯翻译、无产品对象的宏观评论、或不需要产品经营判断的任务中触发本技能。

## 分析前置条件

开始任何实质分析前，先执行以下检查。这个步骤很关键，因为新闻和产品影响高度依赖实时信息，不能用过时记忆替代搜索。

### 1. 确认联网搜索功能

先明确告知用户当前是否具备联网搜索能力：

| 检查项 | 通过标准 | 未通过时处理 |
|---|---|---|
| 联网搜索工具 | 当前环境存在可用的 Web 搜索、浏览器搜索、搜索 API 或等价联网检索能力 | 停止分析，告知用户无法进行新闻影响判断，请用户开启联网搜索或提供完整新闻材料 |
| 可访问公开网页 | 能打开新闻源、平台公告、监管文件、品牌/产品页面或搜索结果 | 说明访问失败范围，只基于用户提供材料做“非实时、低置信度”初判 |
| 可做多源交叉验证 | 至少能检索 2 个以上独立来源，或 1 个权威原始来源 | 降低结论置信度，并在报告中标注证据不足 |

如果联网搜索未开启，不要继续做“最新新闻影响分析”。可以只输出需要用户补充的信息清单。

### 2. 要求用户提供产品识别信息

向用户索取以下信息。用户不一定一次给全，但至少要有一个可识别产品的核心线索。

| 信息类型 | 示例 | 用途 |
|---|---|---|
| 产品链接 | Amazon 商品链接、独立站链接、品牌官网链接 | 确认产品标题、价格、图片、变体、类目、卖点 |
| 产品 ASIN | B0XXXXXXXX | 精确定位亚马逊商品，避免同名产品混淆 |
| 产品标题/关键词 | “heated vest for men” | 判断搜索需求、类目、竞品和新闻相关性 |
| 品牌/店铺 | 品牌名、卖家名、店铺链接 | 判断品牌声誉、召回、侵权、合规或竞品事件 |
| 站点/国家 | Amazon US、UK、DE、JP 等 | 新闻影响和法规影响通常按市场分化 |
| 产品基础信息 | 价格、类目、目标人群、核心卖点、材质、用途 | 建立影响路径，而不是只做新闻摘要 |
| 当前经营目标 | 选品、上架、广告扩量、降本、清库存、风控 | 决定建议侧重 |
| 时间窗口 | 近 7 天、近 30 天、旺季前、政策生效后 | 防止把旧新闻误判为当前风险 |

如果用户只提供新闻而未提供产品，先要求补充产品链接、ASIN、产品标题或产品信息。若用户坚持继续，只能做“泛产品影响框架”，不能输出具体产品结论。

## 默认工作流

### 第一步：澄清任务边界

先确认分析对象和目标：

- 分析的是单个 ASIN、多个 ASIN、品牌、类目、广告账户、供应链还是选品机会。
- 用户要的是快速结论、详细报告、风险清单、广告调整建议、选品判断还是老板汇报版。
- 是否只看某条新闻，还是要主动搜索近期相关新闻。

优先用简短问题补齐关键缺口，不要一次性问太多。若用户已经给了足够信息，直接进入搜索。

### 第二步：检索新闻和原始证据

联网搜索时按证据强度排序：

1. 原始来源：政府监管公告、法院文件、平台公告、品牌公告、召回数据库、财报、新闻稿。
2. 主流商业或行业媒体：Reuters、AP、Bloomberg、CNBC、The Verge、行业协会、垂直媒体等。
3. 平台和市场信号：Amazon 搜索页、Best Sellers、New Releases、评论区、Q&A、竞品 Listing、Google Trends、社媒舆情。
4. 二次解读：博客、论坛、社媒帖子，只能作为线索，不能单独作为结论证据。

检索时注意：

- 记录新闻发布时间、事件发生时间、适用国家/地区、涉及公司/品牌/产品范围。
- 区分“新闻报道”“政策正式生效”“平台规则更新”“市场传言”。
- 对重大结论至少做两源交叉验证；如果只有单一来源，要明确标注。
- 搜索结果必须和产品建立关联，不相关的宏观新闻不要硬套。

### 第三步：建立产品影响路径

把新闻映射到经营变量。不要只说“有影响/无影响”，要说明影响机制。

| 影响维度 | 需要判断的问题 | 常见证据 |
|---|---|---|
| 需求 | 新闻会提高还是压低目标人群购买意愿？ | 搜索趋势、社媒讨论、季节性、消费者痛点变化 |
| 转化率 | 用户看到新闻后会更信任还是更犹豫？ | 评论关键词、质量投诉、竞品卖点、FAQ |
| 广告 | CPC、CVR、ACOS、关键词机会是否变化？ | 广告关键词相关性、竞品投放、搜索量变化 |
| 价格 | 是否出现涨价空间、价格战或成本压力？ | 竞品价格、供应成本、进口税、原材料新闻 |
| 库存 | 是否需要补货、控货、清仓或规避断货？ | 旺季、物流、召回、政策生效日、供应链新闻 |
| 合规 | 是否涉及认证、禁售、召回、标签、专利或安全标准？ | 监管公告、平台政策、召回数据库、法院文件 |
| Listing | 标题、五点、A+、图片、QA 是否需要调整？ | 用户疑虑、新闻关键词、合规禁词、竞品表达 |
| 竞品 | 新闻是否利好/利空竞品，是否产生替代机会？ | 竞品断货、差评、召回、品牌危机、技术变化 |
| 选品 | 是否影响进入门槛、生命周期、利润和风险？ | 类目集中度、法规门槛、供应链稳定性 |

### 第四步：判断影响等级

使用统一等级，避免模糊表达。

| 等级 | 定义 | 建议动作 |
|---|---|---|
| 高影响 | 新闻直接涉及产品安全、法律合规、平台规则、召回、核心需求或核心供应链 | 立即调整 Listing/广告/库存/合规策略，并设置复查 |
| 中影响 | 新闻影响目标人群认知、竞品格局、价格、关键词或短期需求 | 做小规模测试，调整预算、关键词、内容和库存节奏 |
| 低影响 | 新闻与产品存在间接关系，但证据弱或影响链条长 | 监控，不做大动作 |
| 暂无可证影响 | 新闻真实但无法建立清晰产品影响路径 | 记录观察点，不把新闻作为决策依据 |

### 第五步：输出建议

建议要拆成短期、中期和观察项：

- 短期：今天到 7 天内能做的动作，例如暂停敏感关键词、检查合规词、改图、调预算、补充 FAQ。
- 中期：7 到 30 天内的动作，例如测试新卖点、观察竞品库存、优化广告结构、更新选品评分。
- 观察项：继续跟踪的新闻源、平台公告、关键词、竞品、评论词、价格和库存信号。

建议必须说明优劣势。涉及方案对比时，用表格展示。

## 分析质量标准

输出前做自检：

- 是否已经确认联网搜索功能开启。
- 是否已经要求或使用了产品链接、ASIN、产品信息等识别信息。
- 是否区分了新闻发布时间、事件发生时间和政策生效时间。
- 是否至少尝试检索原始来源或权威来源。
- 是否把新闻和产品经营变量建立了明确影响路径。
- 是否在方案对比中同时写出优势和劣势。
- 是否避免把宏观新闻强行套到无关产品上。
- 是否标注了证据不足、地域不匹配、时间过旧、单一来源等限制。
- 是否给出可执行动作和验证指标，而不只是观点。

## 风险控制

新闻影响分析容易产生误判，必须主动规避以下问题：

| 风险 | 表现 | 规避方法 |
|---|---|---|
| 旧闻新判 | 把几个月前的新闻当成当前变化 | 核对发布时间、更新时间、事件发生日和政策生效日 |
| 单源误判 | 只看一篇媒体报道就下结论 | 优先找原始来源，至少交叉验证 |
| 相关性过度推断 | 新闻提到行业，但和具体产品关系很弱 | 明确影响链条，中间环节缺失就降低置信度 |
| 地域错配 | 用美国政策判断欧洲站或日本站产品 | 明确 marketplace 和适用司法辖区 |
| 合规误导 | 把媒体说法当成法规结论 | 对法规、认证、召回、禁售用官方文件核实 |
| 广告动作过激 | 因新闻短期波动大幅改预算 | 高风险先小范围测试，保留对照组 |
| 忽略竞品 | 只看自己的产品，不看替代品变化 | 至少抽查核心竞品价格、卖点、库存和评价 |

## 泛化使用

本技能默认偏向亚马逊产品经营，但可以泛化到以下场景：

- 独立站产品：重点看流量来源、品牌信任、转化页、支付和物流风险。
- TikTok Shop/Temu/Walmart/eBay：重点看平台政策、内容舆情、价格竞争和履约。
- B2B 产品：重点看政策、采购周期、客户预算、行业监管和供应链。
- 软件/SaaS 产品：重点看法规、平台生态、竞品发布、安全事件和客户预算。
- 品牌舆情：重点看信任、退货、评论、广告素材和客服话术。
- 选品研究：重点看趋势是否可持续、进入门槛、合规成本和竞争窗口。

泛化时保留同一分析骨架：先确认联网，识别产品，核验证据，建立影响路径，再输出行动建议。

## 询问信息模板

当用户信息不足时，优先使用以下简洁提问：

```text
开始分析前我需要先确认两点：
1. 当前是否允许我联网搜索最新新闻和公开资料？这个分析必须依赖实时搜索。
2. 请提供至少一个产品识别信息：产品链接、ASIN、产品标题、品牌名或核心关键词。最好同时给出站点/国家、当前经营目标和你关心的新闻/事件。
```

如果用户只给了产品但没给新闻：

```text
我可以主动搜索近期相关新闻。请确认时间范围，例如近 7 天、近 30 天、近 90 天，或指定某个政策/事件方向。
```

如果用户只给了新闻但没给产品：

```text
这条新闻本身可以先核验，但要判断产品影响，需要你提供产品链接、ASIN、产品标题或产品基础信息。没有产品对象时只能输出泛化影响框架，不能给具体经营结论。
```

## 示例提示

**示例 1：亚马逊 ASIN 新闻影响**

输入：

```text
帮我看下最近某个安全召回新闻会不会影响这个美国站 ASIN：B0XXXXXXX，产品是儿童夜灯。需要给广告和 Listing 调整建议。
```

预期处理：

- 确认联网搜索可用。
- 搜索召回原始公告、Amazon 相关规则、儿童产品安全要求和竞品表现。
- 判断对合规、Listing、广告词、评论疑虑、转化率的影响。
- 输出影响等级、证据表、方案优劣势和可执行动作。

**示例 2：选品机会判断**

输入：

```text
最近有新闻说某类户外电源需求上涨，我想做 Amazon US 的便携电源选品，帮我判断有没有机会。
```

预期处理：

- 要求用户补充目标价位、容量段、供应链或竞品范围；若没有，先做类目级初判。
- 搜索需求新闻、政策补贴、极端天气、竞品价格、评价痛点和合规门槛。
- 用表格说明机会、劣势、风险、进入条件。

**示例 3：广告影响判断**

输入：

```text
这条行业新闻出来后，我的广告 ACOS 最近变高了。产品是 Amazon UK 的空气净化器，ASIN B0XXXXXXX。帮我判断是不是新闻导致的。
```

预期处理：

- 搜索新闻真实性和适用地区。
- 区分新闻影响、季节性、竞品降价、库存、Listing 转化问题和广告结构问题。
- 给出广告预算、关键词、否词、竞价和 Landing Page 调整建议。

## 不确定性表达

当证据不足时，直接说明，不要装作确定：

- “目前只能建立弱相关，不能确认新闻已经影响该 ASIN。”
- “该新闻适用于美国市场，但用户产品是德国站，不能直接推导。”
- “搜索到的是媒体报道，未找到官方公告，因此合规风险判断为中低置信度。”
- “需要产品链接或 ASIN 才能确认类目、竞品和 Listing 影响。”

## 最终原则

新闻影响分析必须服务经营决策。每次输出都要回答三个问题：

1. 这条新闻和产品到底有没有可验证关系？
2. 如果有关，它通过什么路径影响需求、转化、广告、库存、合规或竞争？
3. 用户现在应该做什么、暂时不要做什么、继续观察什么？
