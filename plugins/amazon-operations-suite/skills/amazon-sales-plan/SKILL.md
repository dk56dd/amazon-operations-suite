# 销售计划 Skill

中文名称：亚马逊销售计划  
English name: Amazon Sales Plan

## 目标

帮助用户把亚马逊商品的市场机会、竞品销量、价格带、广告承接、库存约束和利润风险，转化成可执行的销售计划。输出必须包含保守方案和激进方案，并用表格展示关键假设、优劣势、执行动作和风险边界。

这个 skill 不只服务单个品类。保持约 50% 泛化能力：可用于新品上市、老品增长、旺季备货、广告放量、价格调整、类目迁移、站点扩张、库存清仓和年度/月度销售目标拆解。不要把分析写死在某个类目、某个工具字段或某个固定销量模型上。

## 启动门槛

在做任何市场判断、销量预测或方案制定前，先完成 MCP 可用性检查。

1. 确认用户已开启以下 MCP 中至少一个：
   - Sorftime MCP
   - 卖家精灵 MCP
2. 如果两个 MCP 都未开启，立即停止分析，并提示用户先开启至少一个 MCP。不要用记忆、猜测或公开泛泛数据替代 MCP 数据继续往下做。
3. 如果只开启一个 MCP，可以继续，但要在报告中标注“单一数据源，置信度较低”。
4. 如果两个 MCP 都开启，优先交叉验证竞品销量、关键词热度、价格带、BSR/排名、评论量、上架时间和季节性数据。冲突较大时，以区间呈现，不要强行给单点结论。
5. 用户提供同类产品历史销量数据是可选项。若提供，优先用于校准模型；若未提供，则基于 MCP 竞品和市场数据建立区间假设，并明确说明缺口。

## 触发场景

当用户表达以下需求时使用本 skill：

- 制定亚马逊新品销售计划、月销量计划、季度销售目标或年度销售目标。
- 根据竞品销量和关键词数据判断一个产品能不能做、能卖多少、要备多少货。
- 要求输出激进、保守两套销售方案。
- 需要拆解广告预算、自然单目标、广告单目标、库存周转和阶段性动作。
- 想比较不同目标、不同价格、不同广告投入或不同备货节奏的优劣势。
- 有历史销量表、同类产品销量数据、竞品 ASIN 列表、关键词表或广告数据，需要转化成销售计划。

## 输入信息

优先从用户和 MCP 获取以下信息。不要一次性追问过多；能从工具中查到的先查，缺口再问用户。

| 信息 | 用途 | 是否必需 | 缺失时处理 |
|---|---|---:|---|
| 站点/国家 | 决定市场规模、季节性、价格带 | 是 | 追问 |
| 产品名称/类目/核心关键词 | 锁定分析对象 | 是 | 追问 |
| 竞品 ASIN 或同类产品 | 建立销量基准 | 否 | 用 MCP 搜索代表性竞品 |
| 用户产品价格/成本/毛利 | 判断目标是否可盈利 | 否 | 用价格带估算并标注假设 |
| 当前库存/补货周期 | 判断计划是否可执行 | 否 | 输出库存风险提示 |
| 广告预算/目标 ACOS | 拆广告单和预算 | 否 | 用保守区间估算 |
| 历史销量数据 | 校准预测模型 | 否 | 不阻塞，改用市场区间 |
| 上架阶段 | 区分新品、成长期、成熟期、清仓 | 否 | 询问或按新品处理并说明 |

## 数据优先级

按以下顺序使用数据：

1. 用户提供的真实历史销量、广告、库存和利润数据。
2. Sorftime MCP 或卖家精灵 MCP 获取的竞品销量、关键词、BSR、价格、评论和趋势数据。
3. 用户明确认可的业务假设。
4. 行业经验区间。

不要把第 4 类经验区间包装成事实。凡是估算，都要写明“估算依据”和“置信度”。

## 分析流程

### 1. 前置检查

先输出一小段检查结果：

- MCP 状态：Sorftime / 卖家精灵是否可用。
- 数据来源：用户数据、MCP 数据、估算数据分别有哪些。
- 是否允许继续：只有至少一个 MCP 可用时才继续。
- 关键缺口：列出会影响结果的缺失信息。

如果 MCP 不可用，回复应简短直接：

```markdown
当前不能开始销售计划分析：尚未确认 Sorftime MCP 或卖家精灵 MCP 可用。请先开启其中至少一个 MCP；开启后我再继续拉取竞品销量、关键词热度和价格带数据。
```

### 2. 市场与竞品基准

选择 5-10 个同类竞品，覆盖头部、腰部和低位样本。不要只看头部竞品，否则容易把计划做得过激。

输出竞品表：

| 竞品/ASIN | 月销量估算 | 价格 | 评论量 | 排名/BSR | 主要优势 | 主要劣势 | 可参考程度 |
|---|---:|---:|---:|---|---|---|---|

判断重点：

- 市场是否集中在少数头部商品。
- 价格带是否清晰，用户产品是否有价格空间。
- 评论门槛是否过高。
- 新品是否仍有进入窗口。
- 关键词需求是否能支撑目标销量。
- 季节性是否会导致短期误判。

### 3. 历史销量校准

如果用户提供同类产品历史销量数据，先做清洗和校准：

| 字段 | 检查点 | 处理方式 |
|---|---|---|
| 日期 | 是否连续、是否跨旺季/淡季 | 缺失时按周/月聚合 |
| 销量 | 是否存在断货、异常峰值 | 分离真实需求和库存限制 |
| 价格 | 是否有促销、券后价变化 | 与销量变化一起解释 |
| 广告 | 是否有预算变化、ACOS 波动 | 区分广告拉动和自然增长 |
| 库存 | 是否断货或补货延迟 | 断货期不直接当作需求下降 |

校准方式：

- 若历史销量稳定，使用移动平均和季节系数修正。
- 若历史销量波动大，使用 P25/P50/P75 区间，不给单点承诺。
- 若历史数据和 MCP 竞品数据冲突，优先解释冲突来源，再给保守区间。

### 4. 建立两套方案

必须同时输出保守方案和激进方案。两套方案都要能落地，不要把激进方案写成不受约束的理想目标。

| 维度 | 保守方案 | 激进方案 |
|---|---|---|
| 核心目标 | 控制风险，验证转化和利润 | 快速拿量，抢关键词排名和市场份额 |
| 销量假设 | 参考腰部竞品或竞品中位偏低区间 | 参考腰部偏上或头部可追赶区间 |
| 广告策略 | 控预算、筛词、逐步放量 | 加速关键词覆盖和预算测试 |
| 库存策略 | 以不断货为底线，避免库存积压 | 提前压货，但设置止损阈值 |
| 利润策略 | 优先保证毛利和现金流 | 接受阶段性利润下降换排名 |
| 优势 | 风险低、现金压力小、适合验证期 | 增长快、排名推进强、窗口期利用充分 |
| 劣势 | 起量慢，可能错过类目窗口 | 资金占用高，广告和库存风险更大 |
| 适用条件 | 预算有限、数据不完整、供应链不稳 | 预算充足、供应链稳定、目标明确 |

### 5. 计算口径

根据可用数据选择模型，不要机械套公式。常用口径如下：

| 指标 | 计算思路 | 注意事项 |
|---|---|---|
| 月销量目标 | 竞品基准销量 × 可捕获比例 × 季节/价格/评论修正 | 捕获比例要随评论数、价格、广告预算调整 |
| 广告订单 | 广告点击量 × 转化率 | 转化率缺失时用区间 |
| 广告预算 | 点击量 × 预估单次点击成本 | 同时校验目标 ACOS |
| 自然订单 | 总订单 - 广告订单 | 新品早期自然单不要估得过高 |
| 备货量 | 目标日销 × 补货周期 + 安全库存 | 加入断货和滞销两类风险 |
| 销售额 | 销量 × 售价 | 区分标价、券后价和实际成交价 |
| 毛利 | 销售额 - 产品成本 - 平台费 - 物流费 - 广告费 | 成本缺失时必须标注假设 |

### 6. 阶段化执行

把计划拆成阶段，不要只给总目标。

| 阶段 | 时间 | 目标 | 核心动作 | 判断标准 | 调整动作 |
|---|---|---|---|---|---|
| 启动期 | 第 1-7 天 | 验证点击和转化 | 上架检查、主图/标题/价格/优惠、广告初测 | 曝光、点击率、转化率 | 关停无效词，修正 listing |
| 放量期 | 第 8-30 天 | 找到可放量词和目标日销 | 精准词、竞品词、预算分层 | ACOS、订单、排名变化 | 加预算或降价促销 |
| 稳定期 | 第 31-60 天 | 稳定自然单占比 | 优化广告结构、提升评价、控库存 | 自然单比例、利润、库存周转 | 调整价格和补货 |
| 扩张期 | 第 61-90 天 | 扩词、扩品或扩站点 | 长尾词、变体、组合销售 | ROI、复购、排名稳定性 | 决定继续放量或收缩 |

## 方案判断规则

| 判断项 | 保守方案更适合 | 激进方案更适合 |
|---|---|---|
| 预算 | 广告预算有限，需要先验证 | 有明确预算池，可承受试错 |
| 库存 | 补货慢、库存浅、断货成本高 | 供应链稳定，可快速补货 |
| 利润 | 毛利薄，不能长期亏损 | 可接受阶段性亏损换排名 |
| 市场 | 竞品强、评论门槛高 | 市场增长快，新品仍有窗口 |
| 数据 | 数据不完整或单一来源 | 历史数据和 MCP 数据相互支持 |

## 质量控制

在输出前检查以下问题，避免制造新的误判：

- 没有 MCP 可用时是否已经停止，而不是继续分析。
- 是否明确区分事实、估算和假设。
- 是否同时给出保守和激进两套方案。
- 是否用表格展示对比，并写清两套方案的优劣势。
- 是否说明历史销量数据是否被使用，以及如何影响预测。
- 是否把广告、库存、利润和排名目标联动起来，而不是只写销量。
- 是否给出止损线，避免激进方案失控。
- 是否避免过度精确，例如在数据不足时不要承诺具体单点销量。
- 如果需要保存结构化数据，默认使用 PostgreSQL，不另行推荐其他数据库。

## 追问原则

只有当缺失信息会改变结论时才追问。优先追问 1-3 个最关键问题：

1. 站点和产品/类目是什么？
2. 是否已有目标售价、成本和库存？
3. 是否有同类产品历史销量数据或竞品 ASIN？

如果 MCP 已可用且基础信息足够，先给初版方案，不要因为小缺口阻塞。

## 禁止事项

- 禁止在未确认 Sorftime MCP 或卖家精灵 MCP 可用时开始销量分析。
- 禁止把估算销量写成确定结果。
- 禁止只给激进方案或只给保守方案。
- 禁止只讲运营动作，不给销量、广告、库存和风险口径。
- 禁止忽略数据来源和置信度。
- 禁止把用户未提供的成本、利润、预算当作事实。
