# 竞品跟踪 Skill / Competitor Tracking Skill

中文名：竞品跟踪  
English name：Competitor Tracking

## 目标

帮助用户围绕 Amazon 竞品链接或 ASIN 做持续跟踪：先获取对应站点的当前数据，再以 upsert 方式更新到笔记，最后基于当前数据和历史记录分析竞品变化、竞争优劣势、风险信号和可执行动作。

## 触发场景

当用户提出以下需求时使用本 skill：

- 跟踪某个或多个竞品 ASIN。
- 根据竞品链接分析 listing、排名、评分、评论、属性或店铺变化。
- 对比多个竞品在不同时间点的表现。
- 更新竞品笔记、竞品库、竞品监控记录。
- 分析某个站点下竞品当前状态和历史趋势。
- 判断竞品优势、劣势、风险、机会点和后续运营动作。

## 前置条件

开始任何数据获取或竞品分析前，先检查并确认用户已经开启以下 MCP 中至少一个：

- sorftime MCP
- 卖家精灵 MCP
- SIF MCP

如果没有确认到任一 MCP 已开启，停止执行，并用中文提示用户：

```text
需要先开启 sorftime MCP、卖家精灵 MCP 或 SIF MCP 中至少一个，我才能继续获取站点当前数据并更新竞品笔记。
```

不要把 SIF MCP 写成其他名称。不要在 MCP 未开启时用记忆、猜测、网页搜索或旧数据替代当前站点数据。

## 输入要求

用户需要提供：

- 竞品链接或 ASIN，允许一个或多个。
- 对应站点，例如美国站、德国站、日本站，或明确的 Amazon marketplace。
- 可选：目标品类、目标关键词、自家 ASIN、关注指标、分析时间范围、已有竞品笔记路径。

如果用户只提供链接，要从链接中识别 ASIN 和站点；如果无法可靠识别，先向用户确认。  
如果用户只提供 ASIN，但没有站点，先要求用户补充站点，因为同一 ASIN 在不同站点的数据可能不同。

## 数据获取原则

默认获取站点当前数据。数据源优先级如下：

| 优先级 | 数据源 | 使用条件 | 优势 | 劣势 |
|---|---|---|---|---|
| 1 | sorftime MCP | 用户已开启且支持目标站点或目标 ASIN | 适合获取站点实时竞品数据 | 字段覆盖取决于 MCP 能力 |
| 2 | 卖家精灵 MCP | 用户已开启且支持目标站点或目标 ASIN | 适合 Amazon 运营和竞品维度 | 可能存在字段命名或导出结构差异 |
| 3 | SIF MCP | 用户已开启且支持目标站点或目标 ASIN | 可作为竞品数据补充来源 | 需要按实际工具能力校验字段 |

使用 MCP 获取数据时，要记录：

- 数据源名称。
- 获取时间，使用本地日期时间和时区。
- 站点。
- 原始输入链接或 ASIN。
- MCP 返回的关键字段。
- 无法获取的字段和原因。

并发获取多个 ASIN 时，并发数不能超过 5。

## 基础数据维度

每个竞品记录至少尝试获取以下字段：

| 字段 | 说明 |
|---|---|
| ASIN | 标准化后的 ASIN |
| 站点 | marketplace 或国家站点 |
| 竞品链接 | 可回溯的商品链接 |
| 标题 | 当前 listing 标题 |
| 五点 | 当前 bullet points |
| 大类排名 | Best Sellers Rank 的大类排名 |
| 小类排名 | Best Sellers Rank 的小类或细分类排名 |
| 各类产品属性 | 尺寸、材质、颜色、规格、容量、适用场景等可获取属性 |
| 店铺名 | 当前店铺或品牌店铺名称 |
| 评分 | 星级评分 |
| 评论 | 评论数量及可获取的评论摘要 |

在基础字段之外，保留约 30% 泛化字段，用于捕捉不同品类和不同 MCP 能力下的有效信号：

| 泛化字段 | 说明 |
|---|---|
| 价格 | 当前售价、划线价、优惠券、折扣、秒杀或促销 |
| 变体 | 颜色、尺寸、套装、数量、变体数量和主变体 |
| 图片和视频 | 主图数量、视频、A+ 页面、品牌故事等内容资产 |
| 配送和库存 | Prime、配送时效、库存状态、断货信号 |
| Buy Box 和卖家 | Buy Box 卖家、跟卖数量、FBA/FBM 状态 |
| 类目路径 | 当前类目路径和类目归属变化 |
| 关键词信号 | 可获取的自然排名、广告位、核心关键词覆盖 |
| 评论质量 | 近期差评主题、好评主题、评分结构、评论增长 |
| 问答和徽章 | Q&A 数量、Amazon's Choice、Best Seller、New Release 等徽章 |
| 销量估计 | MCP 明确提供时记录销量、月销或趋势；没有来源时不要编造 |

如果 MCP 返回了额外字段，要保留与品类、转化、排名、流量、内容质量、履约、价格竞争相关的字段；无关字段可以放入“原始补充字段”。

## Upsert 到笔记

数据必须以 upsert 方式更新到笔记中：

- 如果笔记中已经存在相同 `站点 + ASIN` 的竞品记录，更新该竞品的当前快照，并追加新的时间点记录。
- 如果不存在，创建新的竞品记录。
- 不删除历史时间点，除非用户明确要求清理。
- 同一时间点重复抓取时，以最新获取结果覆盖该时间点的当前快照，同时保留数据源和更新时间。
- 无法获取的字段用“未获取”或“数据源未返回”标记，不要留空造成误判。

推荐笔记结构：

```markdown
# 竞品跟踪笔记

## 索引

| 站点 | ASIN | 标题 | 店铺名 | 当前大类排名 | 当前小类排名 | 评分 | 评论数 | 更新时间 |
|---|---|---|---|---:|---:|---:|---:|---|

## 竞品记录

### [站点] [ASIN] [短标题]

#### 当前快照

| 字段 | 当前值 | 数据源 | 更新时间 |
|---|---|---|---|

#### 时间序列

| 时间 | 大类排名 | 小类排名 | 价格 | 评分 | 评论数 | 店铺名 | 主要变化 |
|---|---:|---:|---:|---:|---:|---|---|

#### Listing 内容

- 标题：
- 五点：
- 产品属性：
- 图片/视频/A+：

#### 评论和口碑

- 好评主题：
- 差评主题：
- 评分结构：
- 评论增长：

#### 分析结论

- 优势：
- 劣势：
- 机会：
- 风险：
- 建议动作：
```

如果用户指定已有笔记路径，就更新该笔记；如果没有指定，就在当前工作区或用户指定目录生成新的竞品跟踪笔记，并在回复中说明文件位置。

## 分析流程

1. 确认 MCP 开启状态。必须是 sorftime MCP、卖家精灵 MCP 或 SIF MCP 中至少一个。
2. 解析用户输入，标准化为 `站点 + ASIN + 链接`。
3. 获取站点当前数据，并记录数据源、时间、缺失字段。
4. 将当前数据 upsert 到笔记中。
5. 读取同一 ASIN 的历史时间点；如果有多个竞品，也读取同组竞品的历史时间点。
6. 如果只有当前时间点，输出当前横向对比和单点诊断。
7. 如果有多个时间维度，综合多个时间维度一起分析，不只看最新一次。
8. 输出中文分析结论、表格化对比、优劣势和行动建议。

## 多时间维度分析

当笔记中存在多个时间点时，分析要覆盖：

| 维度 | 看什么 | 判断逻辑 |
|---|---|---|
| 排名变化 | 大类排名、小类排名的上升或下滑 | 排名持续上升通常代表流量或转化改善；突然下滑要结合断货、差评、价格和内容变化判断 |
| 价格变化 | 售价、优惠券、折扣、促销 | 价格下降可能带来转化提升，也可能压缩利润或触发价格战 |
| 评分评论 | 评分、评论数、近期差评主题 | 评论增长但评分下降，常见于质量、履约或预期不一致问题 |
| Listing 变化 | 标题、五点、属性、图片、A+ | 文案或内容资产更新后排名提升，可能说明转化或关键词覆盖改善 |
| 店铺变化 | 店铺名、Buy Box、跟卖、履约 | 店铺或履约变化会影响稳定性和转化 |
| 类目变化 | 大小类归属和类目路径 | 类目切换可能影响 BSR 可比性，要避免错误对比 |

如果不同时间点字段不完整，要明确写出分析置信度，避免把缺失数据当成没有变化。

## 分析口径

- 对比必须用表格展示，并同时说明优劣势。
- 数据展示也尽量用表格，便于用户扫描。
- 区分事实、推断和建议。事实来自 MCP 数据和笔记；推断要说明依据；建议要能执行。
- 不要编造排名、销量、价格、评分、评论或店铺信息。
- 类目不同的竞品不要直接比较 BSR 数值，要先说明可比性限制。
- 同站点数据优先，同 ASIN 跨站点数据要分站点分析。
- 当 MCP 数据和笔记历史数据冲突时，优先保留两者并标记冲突，不直接覆盖历史事实。
- 若数据来自不同 MCP，要记录来源差异，并说明可能导致字段不一致。

## 质量检查

完成前检查：

- 是否确认 sorftime MCP、卖家精灵 MCP 或 SIF MCP 至少一个已开启。
- 是否获取了用户指定站点的当前数据。
- 是否标准化了 ASIN 和站点。
- 是否按 upsert 方式更新笔记，而不是覆盖整个历史。
- 是否保留了获取时间、数据源和缺失字段。
- 是否覆盖大小类排名、标题、五点、产品属性、店铺名、评分、评论。
- 是否补充了价格、变体、图片视频、配送库存、Buy Box、关键词、评论质量等泛化字段中可获取的部分。
- 是否在多个时间维度存在时做了综合趋势分析。
- 是否用表格展示数据和优劣势。
- 是否明确区分事实、推断和建议。

## 失败处理

| 情况 | 处理方式 |
|---|---|
| MCP 未开启 | 停止执行，提醒用户开启 sorftime MCP、卖家精灵 MCP 或 SIF MCP |
| 用户未提供站点 | 要求补充站点后再继续 |
| 链接无法解析 ASIN | 请求用户确认 ASIN |
| MCP 不支持目标站点 | 换用已开启的其他 MCP；仍不支持则说明限制 |
| 字段缺失 | 标记“数据源未返回”，不要猜测 |
| 笔记路径不存在 | 创建新笔记，或让用户确认目标路径 |
| 历史数据和当前数据冲突 | 保留冲突记录，标明来源和时间 |

## 示例提示

用户可能这样调用：

```text
帮我跟踪这 5 个美国站竞品 ASIN，更新到竞品笔记里，然后分析谁最近威胁最大。
```

```text
这是竞品链接，站点是德国站。先获取当前数据，upsert 到笔记，再和上周的数据一起分析。
```

```text
把这些竞品做一次当前横向对比，重点看大小类排名、评分评论、标题五点和价格促销。
```

## 推荐回复风格

回复要结论先行，中文表达，避免泛泛而谈。用户关心的是竞品当前状态、变化原因、对我方威胁和下一步动作，所以分析要围绕证据和动作展开。

不要说“可能需要数据”就结束；如果 MCP 已开启且输入完整，应直接获取、更新、分析、输出结论。只有在 MCP 未开启、站点缺失、ASIN 无法确认或数据源明确失败时才停下来让用户补充。
