# 发补货分析 / Replenishment Analysis

中文名称：发补货分析  
英文名称：Replenishment Analysis

## 使用边界

使用本 skill 处理亚马逊运营中的发货和补货决策，目标是把销售速度、库存状态、在途节奏、采购周期、资金约束和断货风险合并成可执行的补货计划。

适用场景包括：

- 用户要求分析“发补货”“补货数量”“发货计划”“断货风险”“库存覆盖天数”“什么时候补货”“补多少货”“哪些 SKU 先发”。
- 用户提供业务报告、库存报表、领星导出报表、优麦云导出报表、Amazon Business Report、FBA Inventory、库存流水、采购在途、海外仓库存等数据。
- 用户开启领星 MCP 或优麦云 MCP，希望直接读取销售、库存、采购、在途、仓库或商品维度数据。
- 用户需要按 SKU、ASIN、父 ASIN、店铺、站点、仓库、发运方式或供应商做补货优先级排序。

不适用场景：

- 只分析广告投放，不涉及库存和补货决策时，应使用广告诊断类 skill。
- 只做选品、竞品、关键词、Listing 文案，不涉及库存周转时，应转向对应 skill。
- 没有业务报告、库存报表，也没有可用的领星 MCP 或优麦云 MCP 时，不要凭经验编造补货量。

## 开始前准入检查

开始分析前，先执行数据准入检查。因为补货结论会直接影响资金、仓储、物流和断货风险，缺少核心数据时结论很容易误导。

满足以下任一条件才能继续：

| 准入方式 | 必需条件 | 可继续分析 | 说明 |
|---|---:|---:|---|
| 文件数据 | 用户已提供业务报告数据，并已提供库存报表数据 | 是 | 业务报告用于计算销量、趋势和预测；库存报表用于计算可售、在途、可发和断货风险。 |
| 领星 MCP | 当前会话已开启领星 MCP，且可以读取销售与库存相关数据 | 是 | 需要先验证 MCP 可访问，并说明读取到的数据范围。 |
| 优麦云 MCP | 当前会话已开启优麦云 MCP，且可以读取销售与库存相关数据 | 是 | 需要先验证 MCP 可访问，并说明读取到的数据范围。 |
| 数据不足 | 只有业务报告、只有库存报表、只有口头描述，或 MCP 未开启/不可读 | 否 | 只能输出缺失清单和下一步取数建议，不能输出补货数量。 |

如果准入不通过，停止分析并只输出：

```markdown
## 无法开始发补货分析

当前缺失：
- [缺失的数据或 MCP 能力]

需要补充：
- 业务报告数据：建议包含日期、SKU/ASIN、销量、销售额、订单量、转化率或 Sessions。
- 库存报表数据：建议包含 SKU/ASIN、FBA 可售、预留、不可售、在途、本地库存、采购中、预计到货日。
- 或开启领星 MCP / 优麦云 MCP，并允许读取销售、库存、采购和在途数据。

补齐后我再继续计算补货建议。
```

## 数据源优先级

优先使用用户指定的数据源。未指定时按以下顺序处理：

1. 当前会话明确提供的文件或表格。
2. 用户明确开启并授权读取的领星 MCP 或优麦云 MCP。
3. 同一任务中用户指定的本地文件路径。
4. 不使用历史记忆中的旧数据作为当前补货依据，除非用户明确要求用历史快照做示例。

当文件数据和 MCP 数据同时存在时，先说明口径差异，再按用户指定口径分析；若用户未指定，优先使用更新时间更近、字段更完整的数据源。

## 必要字段

先做字段映射，不要假设不同系统的字段名完全一致。字段缺失时要说明影响。

业务报告建议字段：

| 字段类别 | 常见字段名 | 用途 | 缺失影响 |
|---|---|---|---|
| 商品标识 | SKU、MSKU、Seller SKU、ASIN、父 ASIN | 与库存表关联 | 无法稳定合并销售和库存。 |
| 时间 | 日期、报表周期、周、月 | 计算销量趋势 | 只能做静态库存判断，预测会变弱。 |
| 销量 | Units Ordered、销量、订单商品数、发货量 | 计算日均销量 | 无法计算覆盖天数和补货量。 |
| 销售额 | Ordered Product Sales、销售额 | 判断优先级和资金效率 | 可继续，但无法排序销售价值。 |
| 流量转化 | Sessions、Page Views、CVR、Buy Box | 判断销量变化原因 | 可继续，但趋势解释会变弱。 |
| 价格/利润 | 售价、毛利、毛利率、贡献利润 | 判断补货优先级 | 可继续，但无法做利润优先排序。 |

库存报表建议字段：

| 字段类别 | 常见字段名 | 用途 | 缺失影响 |
|---|---|---|---|
| 商品标识 | SKU、MSKU、ASIN、FNSKU | 与业务表关联 | 无法合并。 |
| 可售库存 | FBA 可售、Available、Fulfillable | 计算当前可卖天数 | 无法判断断货时间。 |
| 预留/不可售 | Reserved、Unfulfillable、FC Transfer | 判断实际可用库存 | 可能高估库存。 |
| 在途库存 | Inbound、Shipped、Receiving、采购在途 | 计算未来覆盖 | 可能误判补货紧急度。 |
| 本地/海外仓库存 | 本地仓、海外仓、可发库存 | 判断可发货源 | 无法给发运方案。 |
| 采购信息 | MOQ、箱规、采购中、供应商交期 | 调整补货数量 | 只能给理论补货量。 |
| 时间信息 | 预计到货日、发货日、船期、空派时效 | 判断断货缺口 | 无法拆分加急和常规发运。 |

## 分析参数

如果用户没有给参数，先使用保守默认值，并在报告中标注“可调整假设”。不要把默认值伪装成真实业务事实。

| 参数 | 默认口径 | 可调整原因 |
|---|---|---|
| 销量观察期 | 最近 7 天、14 天、30 天同时看 | 防止单一周期被促销、断货或广告波动扭曲。 |
| 主预测销量 | 近 14 天日均销量为主，结合 7 天趋势修正 | 兼顾近期变化和短期稳定性。 |
| 安全库存 | 7-14 天销量 | 应按供应链稳定性、利润和断货代价调整。 |
| 目标覆盖天数 | 45-60 天 | 可按海运、空运、采购周期和资金压力调整。 |
| 采购/生产周期 | 用户提供优先；缺失时只做敏感性区间 | 交期不明时不能给唯一确定补货量。 |
| 物流周期 | 按发运方式拆分，空派/快递短，海运长 | 影响是否需要加急补货。 |
| 最小补货约束 | MOQ、箱规、整托、整柜、预算 | 理论数量必须转成可执行数量。 |

## 标准工作流

### 1. 确认输入和范围

先确认以下范围，并写入报告开头：

- 站点、店铺、仓库范围。
- 分析周期和数据更新时间。
- 分析维度：SKU、ASIN、父 ASIN、变体、店铺或供应商。
- 数据来源：业务报告、库存报表、领星 MCP、优麦云 MCP。
- 输出目标：补货数量、发货优先级、断货预警、采购建议、物流方案或资金测算。

### 2. 清洗和合并数据

处理数据时遵循以下规则：

- 用 SKU/MSKU 作为主键；SKU 不稳定时用 ASIN + 店铺 + 站点辅助匹配。
- 同一 SKU 多仓库存要分仓保留，再汇总成可售库存、可调拨库存、在途库存。
- 销量为 0 的 SKU 不直接判定无需补货，要检查是否近期断货、Listing 异常、广告关闭或新品未启动。
- 库存异常值需要单独列出，例如可售为负、在途无预计到货日、SKU 无销售但库存很高、销售高但库存缺失。
- 日期、数量、币种、站点单位必须统一；无法统一时先说明，不做跨口径混算。

### 3. 计算核心指标

至少计算以下指标：

| 指标 | 计算口径 | 用途 |
|---|---|---|
| 7 天日均销量 | 最近 7 天销量 / 7 | 判断近期加速或衰退。 |
| 14 天日均销量 | 最近 14 天销量 / 14 | 作为主预测基准。 |
| 30 天日均销量 | 最近 30 天销量 / 30 | 判断中期稳定性。 |
| 趋势系数 | 7 天日均 / 30 天日均 | 判断销量是否明显变化。 |
| 预测日销 | 14 天日均 * 趋势修正系数 | 用于补货计算。 |
| 可售覆盖天数 | FBA 可售 / 预测日销 | 判断断货风险。 |
| 全链路覆盖天数 | 可售 + 确认可用在途 + 可发本地库存，再除以预测日销 | 判断总体库存压力。 |
| 缺口天数 | 采购/物流到货前所需天数 - 当前可覆盖天数 | 判断是否需要加急。 |
| 建议补货量 | 目标库存 - 可用库存 | 输出理论补货数量。 |
| 可执行补货量 | 理论补货量按 MOQ、箱规、预算、物流方式调整 | 输出实际可执行方案。 |

预测日销建议：

```text
趋势系数 = 近 7 天日均销量 / 近 30 天日均销量
趋势修正系数 = 
  如果趋势系数 >= 1.3，取 1.15 到 1.25
  如果趋势系数 <= 0.7，取 0.75 到 0.9
  否则取 1.0

预测日销 = 近 14 天日均销量 * 趋势修正系数
```

补货量建议：

```text
需求覆盖天数 = 采购周期 + 物流周期 + 上架缓冲天数 + 安全库存天数
目标库存 = 预测日销 * 需求覆盖天数
可用库存 = FBA 可售 + 确认可用在途 + 可发本地/海外仓库存
理论补货量 = max(目标库存 - 可用库存, 0)
可执行补货量 = 按 MOQ、箱规、预算、发运方式取整后的数量
```

### 4. 判断风险等级

按断货时间、销售价值、利润和补货可行性综合排序。

| 风险等级 | 判断标准 | 动作建议 | 优势 | 劣势 |
|---|---|---|---|---|
| P0 立即处理 | 可售覆盖天数小于到货前置期，且销量/利润重要 | 加急发货，必要时拆单空派或快递 | 最大限度降低断货损失 | 物流成本高，可能压缩利润 |
| P1 本周处理 | 覆盖天数接近采购+物流周期，存在断货缺口 | 立即下单或安排最近船期/空派 | 成本和风险相对平衡 | 如果销量继续上涨仍可能断货 |
| P2 正常补货 | 覆盖天数充足但低于目标库存 | 按常规节奏补货 | 资金占用较可控 | 对突发促销或排名上涨反应较慢 |
| P3 暂缓补货 | 覆盖天数高、销量弱、库存积压或利润差 | 暂停采购，优先清库存 | 降低资金和仓储压力 | 可能错过需求恢复 |

### 5. 制定发运方案

当一个 SKU 有断货风险时，不要只给一个总补货量，要尽量拆成“加急保供”和“常规补齐”。

| 发运方案 | 适用情况 | 优势 | 劣势 | 输出要求 |
|---|---|---|---|---|
| 快递/空派加急 | P0 或高利润 SKU 即将断货 | 速度快，能保护排名和销售连续性 | 单件物流成本高 | 写明加急数量、覆盖天数和预计缓解到哪天 |
| 海运/卡派常规 | P1/P2 且库存仍有缓冲 | 成本低，适合批量补货 | 周期长，抗波动弱 | 写明常规数量、预计到货窗口和目标覆盖天数 |
| 海外仓调拨 | 海外仓有可调库存，FBA 即将断货 | 比国内发货快，成本可控 | 依赖仓库处理和尾程时效 | 写明调拨量、调拨后 FBA 覆盖变化 |
| 暂缓补货 | P3、低利润、滞销或库存过高 | 降低资金占用和仓储风险 | 若判断错误会错失销售 | 写明暂缓原因和复查条件 |

## 特殊场景处理

### 新品

新品历史销量不足时，不要直接用 7/14/30 天日均作为唯一依据。结合广告计划、上架天数、转化率、同类款销量、首批备货目标和测款预算，给区间建议。

### 促销和大促

如果存在 Prime Day、黑五、网一、站内 Deal、秒杀、Coupon、广告预算提升等事件，要把促销期和日常期分开测算。

### 断货后恢复

如果 SKU 最近销量下降是因为断货、限流或不可售，不要把断货期低销量当成真实需求下降。应剔除断货天数，或使用断货前稳定销量作为参考。

### 滞销和过量库存

库存覆盖天数过高时，输出清库存建议而不是机械补货。可以建议降价、Coupon、广告清仓、变体合并、移仓、停售或减少采购。

### 多变体

父 ASIN 下多变体要同时看变体销量占比和库存占比。不要只按父 ASIN 总量补货，否则容易出现畅销变体断货、滞销变体积压。

## 质量要求

- 补货数量必须能追溯到数据和公式，不输出无法解释的数字。
- 如果关键字段缺失，明确说明“这个结论的可靠性下降在哪里”。
- 对高风险 SKU 优先给可执行动作，例如“今天下单 300 件，150 件空派保 18 天，150 件走海运补目标库存”。
- 对低风险或滞销 SKU 不要为了完整性强行建议补货。
- 表格中的数值要统一单位，金额要注明币种，日期要注明时区或站点口径。
- 当结论依赖默认参数时，标注“默认假设”，并给出用户可调整的参数。
- 当用户要求企业级运行时，建议把结果沉淀到 PostgreSQL 表中，但不要在用户只要求分析时擅自建库或改系统。

## 可泛化扩展

本 skill 保留泛化空间，用于适配不同公司、不同 ERP、不同物流和不同品类：

- 可以把 Amazon 业务报告替换成 Shopify、独立站、沃尔玛、TikTok Shop 或其他渠道销售数据，只要能提供商品维度销量和库存。
- 可以把领星 MCP、优麦云 MCP 替换成其他 ERP/MCP，但必须同样满足销售数据和库存数据可读取。
- 可以按品类调整安全库存，例如季节品、易断供品、高毛利品、低毛利清仓品采用不同覆盖天数。
- 可以按物流方式扩展计算，例如快递、空派、海运、铁路、海外仓调拨、本地仓补 FBA。
- 可以加入利润、广告、自然排名、Review 风险、仓储费、资金周转等权重，但不要让扩展指标覆盖库存和销量这两个基础事实。

## 触发示例

用户可能这样说：

- “帮我看下这些 SKU 怎么发补货。”
